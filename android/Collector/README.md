## 已实现

- 已绑定设备在打开或返回前台时自动连接，不再输入地址或配对码。先以随机 nonce 和 HMAC 验证设备持有原凭据，再连接 `/v1/info`、10 Hz 遥测、连续 JPEG 画面和 PCM 音频。图像轮询遵循设备报告的目标帧率，Android 接收上限 10 fps，画面旁显示过去约 2 秒的实收帧率。
- 固定横屏：首页最左侧为 56 dp 宽音量柱，中央相机采用 `FIT_CENTER` 显示完整帧，不裁剪、不拉伸；右侧固定 236 dp，上方为六轴图，下方为磁场。没有顶部标题栏，连接、记录与设备状态及「⋮」集中在底栏；详细遥控与设备信息位于二级面板；监听和仰角加减位于首页。空值显示为缺失，不替换成零；过期和断线明确提示。
- 音量柱显示最新一块真实第一逻辑 `mic` 通道 PCM 的 RMS，固定 −60…0 dBFS，不跨块平均、不自动增益、不保持峰值。低于 −60 dBFS 时柱为空，数字静音显示 −∞；dBFS 是数字电平，不是现场声压。等待、收包、连续 1 秒过期和断开有明确状态，失效时隐藏当前柱值。旧 2 秒、固定 ±1 FS 的 `AudioWaveformView` 仍保留在代码与测试中，已经不是首页；原始 PCM 记录不受影响。
- 右上六轴图共用一个外框，左侧加速度 m/s²、右侧角速度 °/s，左右并排显示最近 4 秒，各自使用独立纵轴量程。XYZ 均为亮绿系，通过实线 / 虚线 / 点线和字母标签区分；间隙不连线，过期时历史曲线变暗并显示状态。4 秒仅限制显示窗口，原始会话记录不截断。
- 右下磁场显示实际 XYZ µT 和标明 X／Y 的“XY投影”箭头，始终提示“航向未校准”。箭头只表示传感器 XY 平面的磁向量方向，固定长度不表示强度，不标北方、地理航向或机器人位置。自身采样时间、接收年龄和实际绘制延迟均计入 1 秒有效期；无效／溢出／过期时隐藏数字和箭头并显示原因，XY 为零不画方向箭头，旧档缺组显示“未提供”。该视图只读磁场，不用保存角度或目标冒充测量。
- 底栏光照 lx 与接近 raw 计数改用 16 sp 文字，「机器人设置」保留磁场与诊断详情。只有芯片实际可用、测量有效且采样时间在 1 秒内才显示数值，饱和／过期显示缺失。磁场只有工厂补偿，没有整机磁校准；光照未做盖板校准，接近不换算厘米。实际检测和误差边界见[协议](../../docs/collector-protocol.md)。
- 底部右侧「⋮」打开「记录」「机器人设置」。首页中间直接提供声音监听开关和仰角加减按钮。记录面板提供开始 / 停止、中文事件标记、本地会话、回放与导出；设置面板提供绑定状态、重连、遥控和明确提交的抬头角度。实时监听及回放声音默认关闭，需用户显式开启。
- 系统文件选择器导出完整 ZIP。App 不申请手机摄像头、麦克风或全盘存储权限。
- 断线自动重试；已失联时通过 UDP 8082 广播寻找同一绑定 ID，验证签名并重新做 HTTP nonce 挑战后才迁移地址，健康连接不因重复发现抖动。地址迁移保留当前记录，不自动提交角度或遥控命令。不同 `boot_id` 分段；图像和音频启动标识复核；音频序号丢失、流重连、写盘丢弃切分 WAV，保留事件。

当前采集仅在 App 前台运行。App 内菜单、记录和设置浮层的打开 / 关闭不停止采集或记录，也不自动开始记录或发送动作；回放和导出仍必须先停止记录。切换应用、锁屏或关闭 App 时自动停止连接并封存会话，没有后台服务。返回前台会自动连接，但不会自动开始录制或监听。地址、设备 ID 与令牌保存在 App 私有设置中，不写日志或会话文件；禁止备份，不包含在公共 APK 内。

0.4.4 音量柱沿用 0.4.2 的麦克风判鲜修正：先取快照，再在实际绘制时读取同一 Android 单调时钟 `elapsedRealtime()`，避免刷新之后的新样本被旧时钟误判。仍在连续 1 秒没有新音频时显示过期，没有放宽阈值；状态位于柱下方固定位置。这项修正不代表模拟器卡顿或真实断流已解决。

布局以横屏 16:9 为主；0.4.4 已通过原生 UI / HUD 检查，包括 800×450、640×360、640×480 dp 合成尺寸，逐图检查无裁切。相机在不同屏幕比例中继续等比留黑边。未来使用目标是 vivo X Fold3 与 Epson 1080p 有线眼镜，但本轮只调整观察布局，未实现专用外屏投送或传输，也未在该手机或眼镜上安装、输出或验收。合成截图不等于真实眼镜中的可读性与延迟验证。

声音监听使用独立 AudioTrack 线程和最多 4 块的有界队列；播放跟不上时丢弃旧监听块，录制仍保存全部收到的原始通道。断开连接或切后台会自动关闭监听并释放播放资源，恢复连接不会自行打开。首版请求系统低延迟播放模式。Mac 模拟器支持经 CoreAudio 输出，观察台经 AudioTrack 播放；菜单开启或 AudioTrack started 不能单独证明人耳听到。2026-10-31 用户确认 Mac 模拟器听到现场声音属于历史验证，0.4.2 听感及真实手机的延迟仍需另验。[Android 模拟器音频说明](https://developer.android.com/studio/run/emulator-commandline)

## 构建与安装

```sh
cd ~/chan-X20A/android/Collector
./test-host
./build-app
~/Library/Android/sdk/platform-tools/adb -s emulator-5556 install -r build/outputs/apk/debug/StackChan-Collector-debug.apk
```

工具链可通过 `ANDROID_SDK_ROOT` 和 `COLLECTOR_JAVA_HOME` 覆盖。开发签名密钥仅保存在被忽略的 `.private/debug.jks`。当前 APK 为本地可调试构建，用于实机联调，尚未制作发行签名包。

入口 `dev.stackchan.collector/.MainActivity`，不接收 `address` / `token` Intent 覆盖。模拟器保留 `10.0.2.2:8080` 作为 Mac 转发地址；UDP 广播不能穿过模拟器网络时仍重试已保存地址。HTTP 端口为 8080，音频端口遵循已验证设备的信息。

首次绑定由开发电脑迁移已授权的本机凭据，不开放匿名获取令牌接口。对当前可调试安装，先停止该 App，再用 `adb -s <目标序号> shell run-as dev.stackchan.collector` 写私有 `shared_prefs/MainActivity.xml`。XML 的 string 键为 `address`、`token`、`device_id`：地址用该安装可到达的路由，令牌与设备 ID 从本机受保护记录读取。用 XML 编码器生成内容并经标准输入写入，勿将令牌放进命令行、聊天、日志、公开文件或源码。写完后正常启动 Activity，不附 extras；后续只在设备身份复核成功后更新地址。停止 App 后再写是为了避免运行中 SharedPreferences 缓存覆盖迁移内容。其他新设备的面向用户首次绑定流程尚未实现。

首次请求为无 Bearer 的 `GET /v1/discovery?nonce=<32位随机hex>`。仅协议、设备 ID、nonce 与 HMAC 均通过后才发送原令牌；重定向不跟随，错误证明和旧 nonce 不能触发鉴权或媒体请求。UDP 仅发送绑定 ID 与随机 nonce，接收不超过 512 字节的签名回复，固定端口 8080，使用 UDP 源地址作为候选并再次执行 HTTP 挑战。旧固件没有挑战接口时提示升级，不回退为向未知端点裸发令牌。

首页仰角使用减号、加号，每次立即提交当前保存值±5°，到5°或85°边界时截停。未配置时默认13°，已有保存值沿用。请求待确认、正在执行轨迹、断线、遥测过期或转头停用时禁用按钮；长按不重复提交。网络API仍接受0.1°精度，202仅表示已保存并接受请求，不等于实测到位。旧遥测不能解锁新请求，丢响应不会自动重发。底栏保留设置值与有效实测，控件第二行显示调整状态；保护仍由固件有效反馈、原厂限位、速度、停用取消与超时共同执行。

## 记录格式

会话保存在 App 私有目录 `files/sessions/YYYYMMDD-HHmmss-SSS/`，导出 ZIP 保留以下结构：

```text
manifest.json
events.jsonl
segment-001/
  frames.jsonl
  frames/0000000123.jpg
  telemetry.jsonl
  audio.jsonl
  audio-001.wav
segment-002/
  ...
```

`manifest.json` 含格式版本、设备信息、音频通道含义、开始结束时间、分段与计数。状态 `complete` 表示已封存；`recording` 表示尚未正常封存（例如系统强杀），`error` 表示写入错误。不要将未封存记录当作完整采集。写入过程中周期刷新 WAV 头和 JSONL；突发断电仍可能丢失最近一小段尚未刷新的索引。

每条数据保留设备 `boot_id`、`seq`、`timestamp_us`，另附 Android `receive_elapsed_us` 和 `received_wall_ms`。同一启动内可按设备单调时间对齐，跨重启需结合分段和主机接收时间。主机接收时间包含网络延迟，不代表已完成精密时钟同步。App 回放以主机接收时间为时间轴，原始设备时间保留在 UI 和导出中。

0.4.3 的 `magnetometer/light/proximity` 保留在原始 `telemetry.jsonl`，不截断或替换无效 raw，也不新增伪造的距离、航向 CSV。三组各有自己的序号、读取完成时间与 valid；最新快照并非无遗漏历史，不能用顶层 IMU 序号代替环境采样序号。回放沿用有效性和 1 秒鲜度规则，遇到接收中断也显示过期，旧档缺字段保持“未提供”。

音频文件为无压缩 PCM16LE WAV，格式遵循每块头中的采样率和通道数。两个通道按设备报告的 `mic` / `reference` 使用，不能称为立体声双麦克风。`audio.jsonl` 包含每块的 WAV 文件名、样本偏移、字节偏移和采样参数。音频丢块会新建 WAV，不补伪造静音。图像和遥测为轮询快照，序号跳跃可反映设备采样快于轮询，不自动等同网络丢包。

事件包含开始 / 停止、手动标记、断线 / 重连、设备重启、音频间隙、写盘队列丢弃和新分段。256 项有界队列由独立线程写盘，避免阻塞 UI；队列满时计数并标记间隙。记录容量取决于手机剩余存储；写入失败会结束当前记录并显示错误。没有自动上传或自动清理。

## 验证

`./test-host` 验证音频协议、运动窗口、私有绑定的地址/ID规则，以及 HMAC 身份证明的错误 ID、nonce、重放、密钥和编码拒绝。真实 `CollectorClient` 的 HTTP 逻辑依赖 Android 的 JSON 实现，通过 `bash test-android-runtime <目标序号>` 在独立测试 APK 中验证：挑战优先、错误证明/重定向不发送 Bearer、角度单次提交、409 与左右控制隔离、丢响应及重连不重发；另有记录、图表和角度控件测试。0.4.1 增加纯黑绿字绿线、紧凑图表、真实音频振幅与异常状态，以及横屏 16:9 / 4:3 的合成布局检查。`COLLECTOR_BUILD_ONLY=1 bash test-android-runtime` 只构建测试包，不操作设备。

拿到实际导出 ZIP 或从模拟器私有目录拉出的会话后运行：

```sh
python3 tests/verify-session.py /path/to/session.zip
```

该检查核对 manifest 计数、boot 分段、序号去重、JPEG 标识、WAV 参数、样本/字节索引以及 WAV 内不跨缺失音频序号。它不播放或输出现场媒体内容。

端到端验收还需在模拟器 / 手机运行：连接、录制、打标、停止、回放、SAF 导出、切后台停止、重启与断网恢复。构建和主机测试通过不代表上述已通过；实际证据由项目根 `docs/` 的联调记录维护。

局域网 HTTP 配对码用于访问限制，链路没有加密。首版限定同一受信任 Wi-Fi 内使用。摄像头、声音和传感器记录是用户本地数据，不应提交版本库。
