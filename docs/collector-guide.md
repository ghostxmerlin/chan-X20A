# StackChan 观察台使用说明

首版使用独立采集固件与独立 Android App。保留官方板级驱动，替换出厂业务入口；无需出厂账号、云服务或官方 App。实施阶段和后续路线见 [采集计划](collector-plan.md)，数据格式见 [协议](collector-protocol.md)。

## 0.3 肩上采集版

2026-10-31 更新至固件 collector-0.3.6、Android 观察台 0.3.6/code7。遥控 CH 6 / ID 1（接受广播 0）。开发时 USB 接**底座 USB-C**。用户已确认文字圈旋转正常、遥控只有左右转头；此前位置回传损坏的根因仍未解决。实际状态见 [交接记录](session-handoff.md) 最新段。

- 观察台改为加速度、角速度两张最近 8 秒三轴曲线，固定 X 蓝 / Y 绿 / Z 橙，标注单位和实际接收率；触摸缩到画面下方小状态区。
- 记录重点是第一视角、六轴、遥控输入、舵机反馈、电量、链路和事件。快捷标记提供步行、静止、转身、颠簸、遥控转头。
- 实机短测六轴平均约 50 Hz、无缓存缺口，但读取仍有调度抖动；本轮小幅动作/正式版最终记录的视频实收分别为 5.04 / 4.00 fps，早先两段为 5.18 / 5.73 fps。目标 10 fps 尚未达到，不承诺固定 5 fps；短窗口显示值会波动。
- 新固件按 50 Hz 目标读取六轴、批量传回；导出增加 `motion.csv`、`remote.csv`、`servos.csv`，仍保留所有 JSONL、JPEG 和音频索引。加速度包含重力，不能直接用于积分还原步行轨迹。
- 页面显示官方遥控器需使用的频道；遥控器设同频道，目标 ID 0 或 1。开机准备遥控接收器，并尝试一次 13° 启动俯仰（有效行程的 10%）。摇杆与姿态模式均仅执行左右转动，上下输入保留作数据；观察台显示机器人真实开关状态，可点“停止转头”或“启用转头”。
- 保留水平 ±128°限位、启动俯仰的 5–85°限位，速度采用原厂遥控值（通常 600，协议上限 1000）。连续输入沿用原厂平滑；停止后再启用不重放旧输入。0.3.4 将位置回传有效性与开关分开，回传无效显示“位置回传暂缺”，不再擅自清除启用请求。观察台退出不影响独立遥控；机械全行程和带肩动作仍需专项验收。
- 遥控输入和舵机反馈分别显示；上下输入只记录，不作为已执行目标。官方协议没有原始摇杆、遥控器 IMU 或心跳；页面不把安静的遥控器误报为断线。辅助按钮仅记录，未配置 GPIO2 附件输出。

外出采集仍有边界：App 当前只支持前台记录，**锁屏/切后台会封存并停止**；机器人不具备本地 SD 断网补录，离开连接网络后不会自动补回媒体。实际出门需先让手机和机器人加入同一个可用的 2.4 GHz 网络，核对录像、原始运动、遥控频道和电量，再开始短段测试。手机热点直连、省电策略、后台服务、时钟校准、固定安装姿态和长时续航均未验收。

0.3.6 最终固件与 APK、源码和验证状态保存在 `artifacts/collector-0.3.6-black/`；旧版产物保持不变。开关保持不等于实际动作或位置数据已通过验收。

## 开始观察

1. 机器人通电后显示绿色笑面男，文字圈缓慢旋转。轻触屏幕打开绿色信息页，查看当前 IP 和 32 位配对码；配对码分两行显示，输入时连在一起。再次轻触返回首页。
2. Android 安装 `android/Collector/build/outputs/apk/debug/StackChan-Collector-debug.apk`，打开“StackChan 观察台”。
3. 真手机与机器人连接同一 Wi-Fi，点击右上角“连接设置”，输入机器人屏幕上的 `IP:8080` 与配对码，点击“连接机器人”。IP 可能随路由器分配而变化。
4. App 固定横屏：左侧等比例实时画面与实收帧率，右侧加速度、角速度、触摸、电池及音频电平。左下点击“开始记录”，需要时“打标记”；结束时“停止记录”。
5. 向下滚动右栏，在“观察记录”选择“回放”或“导出”。导出使用 Android 系统文件选择器，生成 ZIP。

声音监听默认关闭。需要听现场声音时，用户手动开启“声音监听”，它播放设备声明为 `mic` 的第一逻辑通道；断线、重启或切后台会自动关闭。回放也默认静音。机器人扬声器保持硬件复位；这项监听是在观察台播放麦克风声音。遥控开机准备，独立于观察台连接。

App 保持前台时采集，并保持屏幕常亮。**切到后台、锁屏或关闭 App 会停止连接并封存记录**；首版没有后台录制服务。配对码只在进程内保存，不写会话文件；进程退出后需要重新输入。不要在记录中强制停止 App，否则会话可能留下“未封存”状态。

## 本机 Android 模拟器

已建立独立 AVD `StackChan_Collector_API_35`（Android 15 / API 35，arm64），没有修改其他项目的 AVD。SDK 为 `~/Library/Android/sdk`，此次模拟器序号 `emulator-5556`。

用户本轮已要求开启声音。模拟器未运行时，可启动支持 Mac 音频输出的可见窗口：

```sh
~/Library/Android/sdk/emulator/emulator -avd StackChan_Collector_API_35 \
  -port 5556 -audio coreaudio -no-snapshot -gpu swiftshader_indirect
```

此 Mac 上模拟器直接连接机器人 IP 的 TCP 返回 `No route to host`，而 Mac 直接访问正常。本轮采用仅监听本机回环的透明 TCP 转发，不解析或生成媒体：

```sh
python3 scripts/collector-emulator-relay.py 192.168.1.42
```

模拟器 App 地址填 `10.0.2.2:8080`，配对码仍是机器人的配对码。脚本同时转发 8080 和 8081；机器人的实际 IP 变化时应重启转发并更新参数。`10.0.2.2` 是模拟器访问宿主机回环的专用地址，见 [Android 官方网络说明](https://developer.android.com/studio/run/emulator-networking-address)。真手机直接使用机器人 IP，无需此脚本。

本机联调令牌保存于 `.private/collector-token`，地址保存在 `.private/collector-address`，均不上传。串口启动日志、媒体和导出文件也仅留本机。模拟器转发会引入一段本机路径，其验证不能替代真手机 Wi-Fi 直连、厂商省电和实际听感测试。

## 首版覆盖范围

| 内容 | 当前方式 |
| --- | --- |
| 图像 | 320×240 连续 JPEG 帧，目标 10 FPS；App 显示实收帧率，保留真实序号和时间；尚无 H.264/MP4 |
| 音频 | 24 kHz / PCM16LE / 两个逻辑通道，设备声明 `mic` / `reference`；不称双麦立体声 |
| IMU | 加速度 m/s²、角速度 deg/s，目标读取 50 Hz，App 约 10 Hz 批量拉取并保存原始样本；附 valid 与读取时间，非硬件 FIFO 全量时刻 |
| 触摸 | 头顶三区、屏幕触摸；没有触摸时 count=0，坐标可能是上次位置 |
| 电源 | 电池百分比、充电状态、有效性和采样时间 |
| 遥控与舵机 | 官方映射角度/速度/按钮、源地址与信号、执行目标、有效位置；无效位置留空，0.3.4 不额外采集负载/电流 |
| 尚未接入 | 光线/接近、NFC、红外、microSD 补录、自主行为与情绪模型 |

固件启动即在内存采集，屏幕持续提示；未录制时不保存媒体文件，App 断开后固件仍保留短暂的内存缓冲。要停止硬件采集可关闭机器人电源。

## 记录格式与故障提示

每次记录有 manifest、事件、JPEG、传感器 JSONL、WAV 和音频块索引。设备重启会更换 `boot_id` 并分段；音频缺包或重连会切换 WAV，缺失不补造样本。设备时间为每次启动内的单调微秒，另外保存 Android 接收时间；未做硬件级同步和单向延迟校准。

仅音频按 24,000 × 2 通道 × 2 字节计算约 96 KB/秒，即每小时约 346 MB；再加 JPEG 与索引。画面尺寸、现场内容与录制时长会影响实际占用，长记录前应确认剩余空间。

`complete` 表示正常封存，`recording` 表示尚未封存，`error` 表示写入出错。“正常封存”不代表采集全程无缺口，仍应查看 events 与丢失计数。存储不足会停止记录并显示错误，不自动删除旧数据。

图像较暗可能来自现场光线；过期提示表示最近未收到新数据。`HTTP 401` 表示配对码不正确；`HTTP 503` 可能是音频被其他客户端占用或图像暂未准备好。首版只允许一个音频客户端，主机验收脚本与 App 应依次使用。

局域网协议为带配对码的 HTTP，没有传输加密；限受信任 Wi-Fi 使用，不映射公网端口。

## 构建、验收与 Wi-Fi 配置

```sh
./scripts/idf.sh build
cd android/Collector
./test-host
./build-app
```

主机协议测试：`python3 -B -m unittest discover -s tests -v`。实机三流检查：

```sh
python3 scripts/check-collector.py 192.168.1.42 \
  --token-file .private/collector-token --duration 60 --camera-poll-hz 20 --output logs/collector-check
python3 android/Collector/tests/verify-session.py /path/to/session.zip
```

本次仅写活动 `ota_1` 的应用区域（`0x510000`），未重写 bootloader、分区表、资产或原厂配置。**不要直接将完整默认 flash 命令当作后续部署步骤**：重新识别设备、读取当前活动分区、核对镜像大小与摘要后再写应用。本次端口 `/dev/cu.usbmodem1301`，MAC `<STACKCHAN_MAC>`；另一个 `/dev/cu.usbmodem3101` 是 StickS3，不能误刷。

固件优先使用独立 `collector` 配网覆盖项，否则读取原机保存的 Wi-Fi。需要换网时，可在正确机器人 USB 串口（115200）发送一行 JSON：

```json
{"cmd":"wifi","ssid":"YOUR_2_4_GHZ_SSID","password":"YOUR_PASSWORD"}
```

设备仅写独立 `collector` NVS 后重启，保留原厂 Wi-Fi/校准配置。勿把含密码的真实命令或原始串口日志提交到仓库。原机恢复镜像仍为 `backups/stackchan-original-1.6.0-20261030.bin`，本地采集镜像不是出厂恢复镜像，尚未进行恢复演练。
