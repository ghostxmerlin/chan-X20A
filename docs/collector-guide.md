# StackChan 观察台使用说明

## 当前：Mac 网页与基础固件

Mac 端打开 http://127.0.0.1:8787/；服务未启动时双击 `scripts/open-stackchan-monitor.command`。显示实时机身画面、声音电平、运动/环境、舵机反馈、ASR/M12，声音监听需手动开启。M12 已独立显示检测坐标示意与实际结果更新率；M12 温度和工作进程已通过 Wi-Fi/SSH 接入，原始视频尚未接入。绑定、启停与读数说明见 [网页说明](../web/monitor/README.md)。现在支持 M12 检测/待机、舵机左右5°步进/启停和仰角保存并应用；点击按钮才发命令，开页/恢复不自动动作。仰角会立即尝试调整，同时保存供下次开机使用；保存成功不代表动作成功。

机器人目前为 **collector-0.4.20**（基础版、温度遥测与网页控制），已关闭机身人脸检测与情绪功能，M12 采用用户明确开启/退出的流程。下面 Android 人脸框等是历史版本说明，当前实际状态以[交接](session-handoff.md)为准。

## 0.4.3 环境数据

0.4.3 接入了首页底栏的“光”照度 lx 和“接近”raw 计数，以及「⋮ → 机器人设置」的磁场 XYZ µT 与诊断状态；0.4.4 另在首页直接展示磁场。实际芯片 ID 识别、配置和采样成功后才显示有效数值；未接入旧固件／旧记录显示“未提供”，读取失败、饱和、溢出或满 1 秒没有新测量时显示缺失，不以零值填充。原始 JSON 会保留各组自己的计数、采样时间、错误及无效 raw，回放使用相同规则；环境快照不保证保存每一个硬件转换结果。

BMM150 磁场经过出厂参数与 RHALL 补偿，仍是运动头部芯片坐标，未做整机硬铁／软铁或安装姿态校准，不是已校准指南针。LTR553 光照由真实双通道换算为 lux，未做机身盖板补偿或照度计对照；接近值只是 0…2047 的反射光计数，不代表厘米。两芯片目标测量频率均为 10 Hz；BMM150 复用现有六轴读取中的 AUX 数据，LTR553 使用独立低频任务，目标频率不是每条测量均被 App 保存的保证。

历史候选中，首版 LTR553 识别后配置失败；初始化改为每次 API 等待 50 ms，仅对 I²C 错误做至多 3 次尝试，间隔 100 ms，错误 ID 或配置不匹配不重试。第二候选初始化成功，用户照光／靠近后的 178.629 秒封存记录可见有效照度最高 21.50 lx、接近 raw 最高 160；暗处 raw `(0,1)` 仍如实标记照度无效。该响应试验属于第二候选，不能当作最终固件的完整并发验收。

最终固件已将运行 API 等待由 10 ms 调为有界 50 ms，迟到轮询至少阻塞 1 tick 并重新排期，不追赶空转；保持独立低优先级任务及 1× 增益。`info.light.initialization` 仅记录启动，info／telemetry 的 `light.runtime` 另记运行调用数、错误数和最近失败地址／错误码／时间，成功恢复不会把旧错误刷新为新错误。最终启动短窗仍有 1 次超时，尚未认定 I²C 根因。

最终 63.597 秒 App 会话正常封存并通过记录校验；255 条遥测中的三组环境快照全部有效。按各传感器序号推进统计，磁场／光照／接近约 10.029／9.150／8.701 Hz，App 分别保存 249／245／242 个不同环境快照；这些组提供最新值，没有无遗漏历史补传。LTR553 在录制首末新增 1,737 次访问、0 次错误，保留的 1 次累计错误发生在录制之前。光照为 7.34–15.897 lx，接近 raw 为 0–9，没有重复人工刺激；短测不证明长期稳定或物理校准。

固件还提供显式 `servo_diag=1` 的 UART 事务缓存诊断，普通 App 不请求大载荷。诊断缓存本身不额外轮询；运动任务在开机至少 5 秒、某轴取得新鲜有效位置且软件轨迹结束后，对该轴死区寄存器 26／27 最多做一次只读探针，失败不重试，不解锁或修改配置，HTTP 只读缓存。扭矩使能寄存器已改为单字节读取。最终启动短窗确认 FRAME_ERR 中断已启用，帧错误计数 95→1,329，不能称串口错误消失。

诊断保留最近位置写入、卸力命令及命令参数前缀，快照时间不等于事务发生时间，旧 `last_error` 需看自身时间。共享 UART 的 32 项事件队列可能漏掉事件，计数只作下界，两轴副本不可相加；零错误计数不能排除线路问题。发送计时是 API 提交，非线路波形；卸力命令 ACK 不证明机械卸力，软件轨迹结束也不证明实测到位。字段定义见[协议](collector-protocol.md)，新增观察手段不表示回传根因已修复。

## 0.4.4 第一视角首页

首页使用纯黑背景、亮绿色文字和线条，不添加发光或阴影。固定横屏，最左侧为 56 dp 宽音量柱，中央为相机，右侧 236 dp 栏上方为六轴图、下方为磁场。顶部没有标题栏，连接、记录与设备状态以及「⋮」集中到底部；光照和接近文字放大为 16 sp。相机采用 `FIT_CENTER`，完整画面等比显示，比例不同时留黑边，不裁剪或拉伸。

音量柱使用**最新一块第一逻辑 mic 通道真实 PCM 的 RMS**，显示当前块的数字电平，固定 **−60…0 dBFS**，不做跨块历史平均、自动增益或峰值保持。低于 −60 dBFS 时柱为空，数字静音显示 −∞；这不是现场声压分贝。等待、收包、满 1 秒过期和断开分别提示，失效时隐藏当前柱值。旧版 2 秒、固定 ±1 FS 的波形组件仍保留在代码与测试中，已不用于首页；原始音频记录不受音量柱显示方式影响。

音量柱沿用 0.4.2 的音频判鲜修正：实际绘制时先取快照，再读取 Android 单调时钟 `elapsedRealtime()`，避免用过早缓存的刷新时间误判新到音频。真正连续 **1 秒未收到新音频**仍标为过期，没有延长阈值。这只修正状态判断，不证明模拟器卡顿或网络问题已解决。

右上六轴图在**一个外框内左右并排**：左为加速度 m/s²，右为角速度 °/s，共享最近 **4 秒**时间范围，各自使用独立纵轴量程，不把不同单位混成同一数轴。XYZ 分别使用实线、虚线、点线及标签，三轴均为亮绿系；缺样处断开，过期时历史曲线变暗并显示状态。4 秒仅是显示窗口，原始 JSONL / CSV 样本继续完整记录，不截成 4 秒。

右下磁场显示实际 XYZ **µT** 和带 X／Y 轴的“XY投影”箭头。箭头仅表示磁向量在传感器 XY 平面的方向，固定绘制长度不表示强度，没有 N／S、航向角或位置推算，始终标注“航向未校准”。只有 available、valid、有限 XYZ 及自身采样时间均有效，且计入接收后和延迟绘制时间仍未满 1 秒时，才显示数值与箭头；失效或过期隐藏它们并说明原因，XY 为零时不画方向箭头。它不使用保存俯仰或请求目标代替实测磁场。

底部右侧「⋮」提供「记录」「机器人设置」；声音监听开关与仰角±5°按钮位于首页底栏中间。记录面板集中开始 / 停止、打标、历史记录、回放和导出；机器人设置集中绑定、重连、遥控开关、输入 / 实测及诊断。打开或关闭这些 App 内浮层不会停止前台采集或录制，也不会自动执行控制。回放、导出仍须先停止记录，切后台 / 锁屏仍会停止并封存，行为没有因页面调整而变化。

## 自动连接与抬头角度

0.4.0 为已绑定机器人增加前台自动连接与断线重试。日常打开 App 即连接，不再输入地址和配对码；同一局域网内地址变化时，App 会寻找并验证已绑定的机器人；发现报文已在真实局域网测试，Android 真机跨 IP 恢复仍待验证。清除 App 数据或换新手机仍需重新建立一次绑定，当前开发安装由本机导入已有授权凭据，没有开放匿名领取凭据的接口。

首页点击仰角减号或加号：每次增减5°、立即保存并尝试调整，下次开机沿用。范围5–85°，到边界截停；未配置时默认13°。断线、状态过期、待确认、正在调整或转头停用时按钮禁用，长按不重复。保存值不等于实际位置；有效反馈不足时不会盲目启动，超时和未执行会明确显示。上下摇杆只触发表情与提示音，中心继续开关屏。

- 保留水平 ±128°限位、启动俯仰的 5–85°限位，速度采用原厂遥控值（通常 600，协议上限 1000）。连续输入沿用原厂平滑；停止后再启用不重放旧输入。0.3.4 将位置回传有效性与开关分开，回传无效显示“位置回传暂缺”，不再擅自清除启用请求。观察台退出不影响独立遥控；机械全行程和带肩动作仍需专项验收。
- 遥控输入和舵机反馈分别显示；上下输入记录并触发表情，不作为已执行俯仰目标。原厂协议没有原始摇杆、遥控器 IMU 或心跳；页面不把安静的遥控器误报为断线。辅助按钮仅记录，未配置 GPIO2 附件输出。
- 遥控器已部署 16 字节中心按压扩展，中心按压序号继续进入原始遥测和 `remote.csv`。用户认为试验中的点头偏慢、幅度小，已决定放弃此动作，现已按用户新要求部署 0.3.9 中心开关屏，`center_input_role=display_toggle`、`nod_trigger=none`，不会由中心按压驱动舵机。B 键仍是独立辅助状态。
- 0.3.9 的中心键按一次灭屏、再按一次亮屏；按住不重复切换，首包/重连建立基线。关屏保留原页，触摸不会唤醒或导航；再开恢复原亮度和当前页面内容。开关不持久化，重启默认亮，且不依赖转头控制开关、舵机反馈或观察台。摄像头、麦克风、IMU 和遥控继续运行；屏幕状态遥测是软件状态，用户已确认“开关正常，页面正常”。

外出采集仍有边界：App 当前只支持前台记录，**锁屏/切后台会封存并停止**；机器人不具备本地 SD 断网补录，离开连接网络后不会自动补回媒体。实际出门需先让手机和机器人加入同一个可用的 2.4 GHz 网络，核对录像、原始运动、遥控频道和电量，再开始短段测试。手机热点直连、省电策略、后台服务、时钟校准、固定安装姿态和长时续航均未验收。

点头调速版 `artifacts/collector-0.3.7-nod-fast/` 已作为弃用试验保留；实心图形版及其并发录制证据保留在 `artifacts/collector-0.3.7-solid/`。当前部署与实机检查以 [验证记录](collector-validation.md) 最新段为准，不能把旧版录制等同于新版通过。开关保持不等于实际动作或位置数据已通过验收。

## 开始观察

1. 机器人通电后显示绿色笑面男，文字圈缓慢旋转。轻触进入摘要，查看 Wi-Fi、相机、麦克风、遥控、电量/充电、三轴加速度与角速度、有效舵机角度。摘要左滑进入实时 syslog，日志右滑回摘要；轻触返回首页。摘要长按打开配对详情，查看 IP 和两行 32 位配对码，输入时连在一起；轻触回摘要。
2. Android 安装 `android/Collector/build/outputs/apk/debug/StackChan-Collector-debug.apk`，打开“StackChan 观察台”。
3. 已绑定的手机与机器人连接同一 Wi-Fi，打开 App 自动连接。「⋮ → 机器人设置」可查看绑定状态、暂停或重新寻找机器人。IP 变化时会自动寻找同一设备；首次新安装的绑定见上节，实际跨 IP 恢复仍需专项验证。
4. App 固定横屏：0.4.4 左侧为音量柱，中央为完整等比例实时画面，右侧为并排六轴图和磁场。打开底部「⋮ → 记录」点击“开始记录”，需要时“打标记”；关闭面板可继续观看首页，结束时再次进入并“停止记录”。
5. 在同一记录面板的“历史记录”选择“回放”或“导出”。两者需先停止当前记录；导出使用 Android 系统文件选择器，生成 ZIP。

声音监听默认关闭。需要听现场声音时，在首页手动开启“声音监听”，它在手机或 Mac 播放设备声明为 `mic` 的第一逻辑通道；断线、重启或切后台会自动关闭。音量显示与原始录制不依赖监听开关，回放也默认静音。这不等于机器人扬声器发声；机器人开机仍保持功放硬件复位，0.4.6在显式上传播放或遥控上／下表情事件后临时启用输出。遥控开机准备，独立于观察台连接。

原装 CoreS3 与 StackChan 底座**没有 3.5 mm 耳机／监听口**，机器人声音输出使用内置 1 W 扬声器。要听采集到的现场声音，可使用现有观察台所在手机或电脑的音频输出。[CoreS3 官方接口](https://docs.m5stack.com/en/core/CoreS3)、[原装底座接口](https://docs.m5stack.com/en/base/StackChan_Body)

App 保持前台时采集，并保持屏幕常亮。**切到后台、锁屏或关闭 App 会停止连接并封存记录**；没有后台录制服务。回到前台会自动恢复连接，录制需重新点击开始。绑定凭据存于 App 私有设置，不写会话文件、不参加系统备份，无需退出后重输。不要在记录中强制停止 App，否则会话可能留下“未封存”状态。

## 机器人扬声器短片试听（0.3.8）

固件提供 `POST /v1/playback`，沿用配对码的 Bearer 鉴权。请求体是无 WAV 文件头的 24,000 Hz、单声道、有符号 16 位小端 PCM，客户端使用 `Content-Type: application/octet-stream`；长度必须为非零偶数，最多 384,000 字节，即 8 秒。它是机器人本体播放入口，当前观察台的“声音监听”和会话回放都不会调用该入口。

整段音频先上传到 RAM，完整接收后才允许单个后台任务播放；上传、播放或清理期间均返回忙（`409`），不排队。`202 Accepted` 表示上传已完整接收并通过截止检查，不代表听到声音或播放完成；完成状态、错误及功放复位状态从遥测中的 `playback` 查看。上传截止为 10 秒，单次接收阻塞最多 3 秒，实际关闭可能到约 13 秒再加调度时间；不完整上传不会启用扬声器。

当前播放音量设为80（旧版试听曾为20），不写 NVS，媒体不落盘；不改变采集共享的 I²S 配置。尝试启用输出后，无论完成或失败都会尝试关闭输出并恢复硬件复位，恢复失败会单独记录。`output_enabled=false` 只表示 codec 运行状态；`hardware_reset_held` 来自寄存器读回，读失败为 `null`，不能仅凭前者宣称硬件静音。

本轮使用仅在本地保存的 4 秒官方日语角色样本，job 1 完整提交 192,000 字节，任务进入 `completed`、播放和清理错误均为 0；实际 TX 配置检查通过，结束后寄存器读回 `hardware_reset_held=true`，输出状态为关闭。未鉴权、空 body 和奇数字节请求分别实测返回 401 / 400，未改变 job 或启用扬声器。

21.357 秒录制已封存并通过验证：160 张 JPEG 全解码、实收 7.577 fps，1,051 音频块和 1,050 IMU 样本序列无缺口，IMU 为 50.013 Hz；写盘丢弃、相机/音频错误与音频跳块增量为 0。4.059 秒输出启用窗口持续收到 33 张 JPEG，203 音频块与 203 IMU 样本序号连续。音频有 8 处时间戳抖动超过 5 ms，序列连续不证明没有杂音；用户听感仍未确认。该次两轴反馈仅 10/147 有效，播放前已大量无效，不能将媒体连续性等同于整机稳定或舵机回传修复。

样本、现场录音和配对凭据均不提交到仓库。该轮试听时曾暂关观察台声音监听以免麦克风声音从 Mac 再次回放，麦克风采集仍用于记录；试听结束时录制停止，监听恢复开启并截图确认，转头请求保持开启。当前状态以最新交接为准。

## 本机 Android 模拟器

已建立独立 AVD `StackChan_Collector_API_35`（Android 15 / API 35，arm64），没有修改其他项目的 AVD。SDK 为 `~/Library/Android/sdk`，此次模拟器序号 `emulator-5556`。

模拟器支持声音输出：App 的 AudioTrack 将 PCM 交给 Android 音频系统，再由 Mac 的 CoreAudio 输出。当前已核对启动参数、AudioTrack started 与未静音，但这些软件状态不等于人耳已听到；0.4.2 最终听感仍需用户确认。2026-10-31 用户曾确认 Mac 模拟器听到现场声音，是旧版历史结果。[Android 官方音频启动选项](https://developer.android.com/studio/run/emulator-commandline)

模拟器未运行时，可启动支持 Mac 音频输出的可见窗口：

```sh
~/Library/Android/sdk/emulator/emulator -avd StackChan_Collector_API_35 \
  -port 5556 -audio coreaudio -no-snapshot -gpu swiftshader_indirect
```

此 Mac 上模拟器直接连接机器人 IP 的 TCP 返回 `No route to host`，而 Mac 直接访问正常。本轮采用仅监听本机回环的透明 TCP 转发，不解析或生成媒体：

```sh
python3 scripts/collector-emulator-relay.py 192.168.1.42
```

模拟器绑定保存的转发地址为 `10.0.2.2:8080`，App 启动时自动使用。脚本同时转发 8080 和 8081；机器人的实际 IP 变化时应重启转发并更新参数。模拟器 NAT 不等同于手机的局域网广播，UDP 发现不能替代此转发配置。`10.0.2.2` 是模拟器访问宿主机回环的专用地址，见 [Android 官方网络说明](https://developer.android.com/studio/run/emulator-networking-address)。真手机直接使用机器人 IP，无需此脚本。

本机联调令牌保存于 `.private/collector-token`，地址保存在 `.private/collector-address`，均不上传。串口启动日志、媒体和导出文件也仅留本机。模拟器转发会引入一段本机路径，其验证不能替代真手机 Wi-Fi 直连、厂商省电和实际听感测试。

## 记录格式与故障提示

每次记录有 manifest、事件、JPEG、传感器 JSONL、WAV 和音频块索引。设备重启会更换 `boot_id` 并分段；音频缺包或重连会切换 WAV，缺失不补造样本。设备时间为每次启动内的单调微秒，另外保存 Android 接收时间；未做硬件级同步和单向延迟校准。

仅音频按 24,000 × 2 通道 × 2 字节计算约 96 KB/秒，即每小时约 346 MB；再加 JPEG 与索引。画面尺寸、现场内容与录制时长会影响实际占用，长记录前应确认剩余空间。

`complete` 表示正常封存，`recording` 表示尚未封存，`error` 表示写入出错。“正常封存”不代表采集全程无缺口，仍应查看 events 与丢失计数。存储不足会停止记录并显示错误，不自动删除旧数据。

图像较暗可能来自现场光线；过期提示表示最近未收到新数据。`HTTP 401` 表示配对码不正确；`HTTP 503` 可能是音频被其他客户端占用或图像暂未准备好。首版只允许一个音频客户端，主机验收脚本与 App 应依次使用。

局域网协议为带配对码的 HTTP，没有传输加密；限受信任 Wi-Fi 使用，不映射公网端口。

  --token-file .private/collector-token --duration 60 --camera-poll-hz 20 --output logs/collector-check

机器人部署仅写核对后的活动 `ota_1` 应用区域（`0x510000`），刷机不写 bootloader、分区表、资产或 NVS。遥控器另行核对为 ESP32-PICO-D4 / 4 MB，已完成整片备份及独立校验，实际应用分区为 `factory / 0x10000`；仅写该应用，首次启动前验证应用写入范围以外字节原样。运行时 PHY 校准等可能更新 NVS，不能将刷写范围校验解释为 NVS 从未变化。遥控器 NVS 初始化出错时停止启动，不自动擦除存储。

**不要直接将完整默认 flash 命令当作后续部署步骤**：重新识别设备、读取当前分区、核对镜像大小与摘要后再写应用。机器人与遥控器的应用偏移不同，也不能用于其他设备。

固件优先使用独立 `collector` 配网覆盖项，否则读取原机保存的 Wi-Fi。需要换网时，可在正确机器人 USB 串口（115200）发送一行 JSON：

```json
{"cmd":"wifi","ssid":"YOUR_2_4_GHZ_SSID","password":"YOUR_PASSWORD"}
```

设备仅写独立 `collector` NVS 后重启，保留原厂 Wi-Fi/校准配置。勿把含密码的真实命令或原始串口日志提交到仓库。原机恢复镜像仍为 `backups/stackchan-original-1.6.0-20261030.bin`，本地采集镜像不是出厂恢复镜像，尚未进行恢复演练。
