# 一个机器人，几个身体：平台差异怎么分（2026-11-20）

主人 2026-11-20：Mac 和 StackChan 不是两个机器人、两个库，而是 hello 的两个身体。现在的 `hello_mac` 复制库只为调试，最终合并成一个库、一套服务。

## 哪些能力因身体而不同

| 能力 | 机身 StackChan | Mac | 共用 / 分开 |
| --- | --- | --- | --- |
| 听觉 | 固定麦克风，增益最大，有 M12 风扇底噪 | 选的麦克风 | 格式和耳朵共用；门槛按身体调校 |
| 语音口令 | 硬件 Unit ASR | 系统本机识别，可能没有 | 42 个词和含义共用；有没有分开 |
| 摄像头 | 机身摄像头，约 5.7 KB/张 | Mac 摄像头，压到 8 KB 以内 | 变化判定共用 |
| 认人 | M12，128 维脸纹 | Apple 特征 | **两种脸纹不能互比**：脸纹库按身体分，人名单共用 |
| 身体感觉 | 有 | 没有 | |
| 动作 | 舵机 | 用眼睛动作代替 | 以后 mind 发「意思」，身体自己翻译 |
| 屏幕 / 触摸 | 320×240 触摸屏 | 窗口 + 鼠标 | 单击 / 双击含义相同 |
| 台词 | SD 卡 | 打包在 app 里 | 按情绪标签选，不按编号 |
| 远程升级 | 有 | 没有 | |

## 三层

1. **身体报能力**：连接时第一条消息可以带 `"body": {"kind": "mac", "abilities": {...}}`。没带（机身固件现在就没带）就按来源名认种类，用这一种的默认能力。服务器只看能力，不看名字前缀。
2. **命令按意思**（还没做）：mind 发「同意 / 看这个人 / 惊讶」，机身用舵机，Mac 用眼睛。
3. **调校表**：服务器怎么对待这个身体的声音，在 `server/common/bodies.py` 的 `KINDS[*].tuning`，身体自己不能改。

## 第一步（2026-11-20，分支 bodies）

- `server/common/bodies.py`：种类、能力、调校；`body(source, declared)` 认出是哪个身体。
- 耳朵：原来的 `source.startswith("stackchan")` 一个判断管两件事（是不是 hello 的身体、按不按机身麦克风调校），拆成「是身体」和调校表。机身的调校和以前完全一样；Mac 现在按 Mac 麦克风调校（15 dB 声音门槛、声纹录入不收「不清楚」，降噪保留）。
- 登记：耳朵每次听觉 / 视觉连接开关时写 `bodies` 集合（能力、第一次和最后一次出现、现在几条连接），耳朵启动时把连接数清零。
- mind：`GET /bodies`（每种身体、见过的设备、在不在线）；`strong.py` 的「听觉连接」判断改用 bodies。
- 观察台：`/bodies.html`。

## 以后

- 工具按能力：要舵机的 Docking 工具只给会动的身体；人设知道自己在哪个身体里。
- 合并数据库：每条记录带身体 id；人共用，脸纹库按脸纹格式分。
- 两个身体同时在：谁被点谁聊；同一房间同一句话只算一次；提醒在人最近面对的那个身体上响。
- 服务改成一套服务多个身体：TTS 现在只认一台设备，耳朵的 Docking 只有一个会话，mind 只知道一个机器人地址。
