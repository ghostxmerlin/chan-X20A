# 场景、长期记忆与角色说话

入口：监视台 **设置 → 说话风格 / 场景 / 长期记忆**。仍然由台词区的五个按钮触发，不会自主插话。实现只修改服务器和网页，没有新增 ESP32 任务、遥测或固件。

## 设置

- 办公室、家里、朋友聚会分别保存环境、优先笑点与避开的话题。办公室继续兼容情景页原有的环境说明。
- 切换场景并保存后，近期原话、纪要和视觉上下文从切换时刻重新开始；不会把上一场景的对话、视觉前情带进来。长期认识按场景隔离。
- 所有修改统一保存为新的设置版本。版本冲突拒绝保存，保留表单；重新打开读取最新版本后再修改。
- `后台学习记忆` 和 `说话时参考记忆` 独立。前者关闭时不补学关闭期间的数据；后者只影响说话是否使用已知习惯。
- 角色可以改方言、语速和说话方式。语速空白沿用已有音色。试听按钮使用**已保存**的角色设置与固定文本，不生成笑话，不进入学习或去重历史。

## 记忆如何形成

独立 `soul-memory` 服务每十分钟归纳一次已有数据库观测。首次上线从当前时刻开始，不追溯灌入全部历史。每轮最多三个窗口，恢复时最多追赶 48 小时；模型失败退避五分钟。最近两个窗口可接收晚到的听悟或视觉修订。提取结果先持久化，数据库写入失败重试时不重复请求模型。

- 习惯至少跨三天、六个独立窗口支持，才能从候选变为已认识。
- 固定时段规律按工作日/休息日、本地小时、听觉/视觉分开统计。某天该小时至少有 15 分钟有效观察才进入分母，累计至少五天后形成认识。覆盖是分钟观测估计，不代表连续录像；离线不是反证。
- 同一窗口的多路 ASR 和后续修订不会重复计票。身份不可靠时保留未知身份；别人讲述的内容标为听到的说法。
- 矛盾证据或超过 30 天未见的自动认识进入待复核。人工确认、纠正、停用不会被后台覆盖。
- 每次语义变化追加不可变版本；重复命中只更新可重建的指标缓存。恢复历史也追加新版本。

设置页可分页查看、确认、纠正、停用、查看历史并恢复。刚部署时为空是正常情况，不会立刻声称了解长期习惯。

集合：`mind_memory_evidence`（窗口版本）、`mind_memories`（认识版本）、`mind_memory_jobs`（游标、租约、提取缓存和指标）。服务 CPU 上限 20%、内存上限 256 MiB，与听觉进程分离。

## 台词写法 scene-say-v2（2026-11-12 夜，Claude，已部署）

结构不变：仍是「情景＋实时输入 → 一次 terra 调用（reasoning none）」。改的是这次调用里怎么写：

- **立场**：hello 是工位上有主见的宠物，不是同事。不回答问题、不出主意、不追问、不总结讨论。scene-say-v1 的台词多数在复述讨论或像同事一样补一句理性分析，所以无聊。
- **先抓点、再选手法、后写句**：输出 `point`（抓的那个点）、`device`（顺推 / 反话 / 抠字面 / 拿自己说事 / 护短 / 最坏预言）、`text`。每个角色标两种擅长手法；服务端把最近两句用过的手法传进去，让手法轮换。`point`、`device` 记在 utterance 的 `focus`、`joke_type`。
- **放开夸张，守住事实**：v1 要求逻辑成立，又让它从成本和后果里找笑点，结果大量句子落进「……是一回事，……又是一笔账」。v2 规定：人和事只能来自输入，夸张、预言、歪理可以放开说，但要一听就是玩笑。这类老套路写进提示词禁止使用。
- **用滥的词**：服务端统计最近 12 句里在两句以上出现的 2–3 字片段，去掉当前输入本身的话题词，作为「用滥的词」传进去。每次修掉一个口癖都会冒出新的（申请、请假、考勤），所以靠统计，不靠写死的清单。
- **输入更好读**：实时输入按新到旧排列，标「N秒前」、谁说的、听不清和另一种听法。环境说明移到 system。
- 回放：在今天 28 个真实台词的上下文上（17 条 scene-v1，11 条 v2），用同样输入对比 v1 重写和 v2，单次 1.3–2.9 秒，与 v1 相当。三轮共约 $0.44。私有对照在本机 scratchpad 和服务器 `~/soul-mind/replay-say/`，不进仓库。好不好笑最终由用户试听判断。
- 回退：`scene_speech.messages_v1` / `RULES_V1` 保留。

## 开口前的筛选

2026-11-12 晚修订：在线发言恢复 `b31dc07` 的「情景＋实时输入 → 一次生成」结构。读取与 `/now` 相同的当前情景，并附加实时原话/纪要/视觉、长期认识、近期台词及当前角色。重点选择规则在 `scene_speech.py` 同一提示词内执行；不再在线调用 `attention.choose` 或旧的多候选生成/修复。旧模块仅留作历史回放。返回只含一句 `text`，不伪造模型选题诊断。

台词调用单独使用 `gpt-6.1-terra`、`reasoning_effort=none`、最多128输出token；记忆及情景后台模型不变。服务端耗时单独记录为 `server_ms`，页面将其与 TTS 起播时间分开显示。超时12秒仅用于故障退出，绝不计作3秒达标。真实回放10次生成（含上下文读取）均1.316–1.923秒；不代表网络尾延迟有保证。以下两阶段选题说明为此前版本记录。

先检查机器人嘴连接和 TTS 模式，再从最近两分钟提取证据。合并同一语段的 sherpa/听悟结果，过滤自声、弱识别和停用来源。未结束的旧纪要不会无限续期，视觉新鲜度按真实帧时间计算。

最新视觉分钟不清楚时，保留其不确定性，并继续寻找两分钟内上一段独立、清楚的观察；不恢复同一分钟已被取代的旧版本，也不越过场景切换或时间边界。没有可靠线索时，API 返回 `409 / code=no_situation`，页面区分语音分歧、识别不确定、无近期输入与一般服务故障，显示可读原因。

关注判断优先跟上可靠原话：纪要一致时一起采用，不一致或话题变化时服从新原话。已知日常降为背景，新鲜明显视觉变化可提升。情绪标签仍然不可靠，只在同一说话者重复标签且伴随声学变化时提供提示，不伪造模型强度分数。

生成器围绕一个话题产出最多三条候选，通常 8–24 字，硬上限 40 字；检查引用、长度、格式和近期重复，最多修复一次，不截句。强制接话而非复述全部经过；笑点偏好不是事实。模型的引用检查不能证明每句语义真实，实际笑点与方言质量仍需听感调节。

关注、生成、有限修复共享原有日预算，每次模型调用最多 45 秒，网页等待最多 180 秒。点击停止、改变嘴模式或保存新设置会取消旧生成，防止稍后突然开口。正在执行的模型 HTTP 请求仍可能完成计费。

台词历史默认只传简短字段；点 **为什么说这句** 才读取关注结果、证据、认识和发音指令。不向页面暴露 API 密钥或克隆音色 ID。

## 部署、验证与回退

运行 `server/mind/deploy.sh` 更新 mind/eye/notes/memory 四个服务；运行 `node web/monitor/service.mjs stop` 后 `start` 更新本地代理。现有数据库设置会合并新字段，保留身份、办公室环境和传感器/嘴的开关。没有刷写固件。

回退：设置 `speech.pipeline = "v1"` 可回到旧生成路径；关闭 `memory.learning` 停止学习，关闭 `memory.apply` 停止引用；历史保留。若要完全撤销程序，应恢复先前服务代码并停用 `soul-memory`，不要删除数据库历史。
