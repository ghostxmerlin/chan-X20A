# mind v3：读 eye 结果，分钟结束后约 40 秒出"此刻" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 分钟包里加入这一分钟的 eye 结果（代号 `e1`）。新提示词 v3 以它作为画面的主要依据，并且输出更短。mind 在分钟结束后 30 秒先出第一版，有晚到的记录（听觉句子、听悟、eye）时再出修订版。v3 先在重跑泳道和 v2 离线对比，用户读过、认可后再切换。

**Architecture:**
- `records.window` 增加读取 `eye_minutes`；`package.build` 把 eye 结果做成 `e1` 条目，计入 codes 和 fingerprint（`BUILDER_VERSION = 3`）。
- `fusion.content_fp` 加入 eye 的摘要，这样 eye 结果后到时内容指纹会变。
- 提示词：`prompts.V3_SYSTEM`。`render` 遇到 v3 且有 eye 结果时写 `e1` 行，不再逐条列出脸。没有 eye 时退回 v2 的写法，照常列出脸。
- 处理时机：`runner.PROCESS_DELAY_MS` 从 80 秒改为 30 秒。`tick` 本来就会复查最近 10 分钟；复查发现某分钟的包出了新版、内容指纹也变了，就调用 `fusion.run_minute(..., revise=True)` 出修订版（reason `revised`）。

**Tech Stack:** Python 3.11；Node 24。

**Spec:** `docs/superpowers/specs/2026-11-11-senses-split-design.md`（第 2 节第 5 条，第 4 节第 4 步）。

## Global Constraints

- 原始表只读；只写 `mind_*` 表；什么都不删，新的结果写成新版本。
- **现在用的 v2 设置不改**：`settings.fusion.prompt` 仍是 v2，直到用户读过对比、认可为止。v3 先只出现在重跑可选的版本里（`prompts.OFFERED`）。
- 修订版的闸门和第一版一样：情景开关、两种感官都关（不调用）、退避、预算、`max_age_min` 都适用。**内容指纹没变就不修订**，不写新版本，也不调用。
- v3 的输出：条目不超过 6 条，每条不超过 40 字；`max_tokens = 2000`（v2 是 4000）。
- eye 结果只取 `source == "model"` 的最新版本，作为 `e1`，ref 为 `{"c":"eye","minute","version"}`。`e1` 算本分钟的画面证据，basis 为 `seen` 时可以引用；在 `language_only` 检查里算"非语言证据"。
- 部署要用户明确说"部署"。

## Review Focus

1. **eye 关着**（没有 `e1`）：期望 v3 仍然可用，退回列脸的写法。测试在 Task 2。
2. **eye 结果在 mind 第一版之后才到**：期望下一次复查时出一版修订，只出一次。测试在 Task 3。
3. **复查时包出了新版，但内容没变**（比如只是迟到的重复行）：期望不调用。测试在 Task 3。
4. **修订那一刻情景开关关着，或者已经超过 max_age**：期望不调用。测试在 Task 3。
5. **eye 结果是 failed、budget 或 backoff**：期望不当作 `e1`。测试在 Task 1。

**Interfaces:**
- Produces:
  - `V3_SYSTEM`：在 v2 的规则上加三条。

### Task 3: 30 秒先出一版，晚到的记录触发修订

**Files:**
- Modify: `server/mind/runner.py`（`PROCESS_DELAY_MS = 30_000`；`tick` 收集复查中改写过的分钟，交给 `fuse(..., revise=True)`）、`server/mind/fusion.py`（`run_minute(..., revise=False)`）
- Test: `tests/test_mind_runner.py`、`tests/test_mind_fusion.py`

**Interfaces:**
- Produces:
  - `fusion.run_minute(..., revise=True)`：
    - 这一分钟的 live 场景已经存在，而且它的 `content_fp` 等于新算出的指纹时，返回 `None`，不写新版本，也不调用。
    - 否则跳过沿用的判断，直接调用，reason 为 `revised`。退避、预算、两种感官都关这几道闸门照常适用。
  - `runner.tick`：复查循环里 `process_minute` 返回 `"written"` 的分钟，如果已经有 live 场景，并且分钟开始时间在 `max_age_min` 之内，就按时间顺序修订。新处理的分钟照旧走 `fuse`。
- [ ] **Step 1: 写失败的测试**：
  - `test_minute_is_processed_30_s_after_it_ends`
  - `test_late_eye_result_revises_the_minute_once`：第一版之后加入 eye 结果，下一次 tick 修订 1 次，再下一次 tick 不再修订。
  - `test_rewritten_package_with_same_content_is_not_revised`
  - `test_no_revision_when_mind_is_off_or_too_old`
  - `test_revision_counts_in_runs_with_reason_revised`
- [ ] **Step 2–4**：确认失败 → 实现 → mind 测试全部 OK
