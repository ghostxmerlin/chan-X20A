# 对话模式第一版（chat v0）

主人 2026-11-14 晚："我想尽快接通 chat，这是后面一起的基础。"
主人的回答：
1. 模型先测一下再定；
2. 声音用无限（`wuxian`）；
3. 谁说话都回应，但可以试着过滤掉远处的声音；
4. 不自动退出（说 pause 才离开）；
5. 要用上情景、纪要、记忆和性格。

现成零件、缺口和耗时，见 `.superpowers/sdd/2026-11-14-chat/research.md`（摸底报告）。第一版只求接通：说完一句，大约 3 秒内回答。流式输出、说"hello"打断、MCP、搜索放到第二版。

## 怎么走

- **入口**：hello 在 `chat` 模式（以 hello 为准，ear 从转发的 `mode_report` 里知道当前模式）。
- **ear**：每识别完一句（`end_speech` 出了文字），如果当前是 `chat` 模式，就马上 `POST /chat/heard` 给 mind。正文带上这些，用 ModeHub 自己的线程池，不阻塞音频：
  - 文字、语言、情绪；
  - 说话人（`speaker`）；
  - 声音特征（`voice`：p、band、`loud_db`，比底噪高多少）；
  - `self`（是不是 hello 自己在出声）；
  - `session` / `id` / `pos`；
  - ear 的 `debug` 计时。
- **mind 对话循环**（新模块 `server/mind/chat.py`）：
  - **过滤**：
    - 跳过 hello 自己的声音（`self` 标记和 `selfvoice.is_hello`）；
    - 跳过 hello 正在说话时听到的；
    - 跳过太短、听不清的（空文字、只有语气词）；
    - **远处的声音**：比当前底噪高不到 N dB（`loud_db` 相对 ear 的底噪），或者声音带标成 `far` / `none`，就当成远处的，不回应。N 先定 12 dB，记进设置，以后按录音调。被过滤的每一句都记下原因。
  - **上下文**（进入对话模式时建一次，之后每轮只增量更新，读库不超过约 100 ms）：
    - 当前情景：最近一分钟的摘要、话题和声音；
    - 当前纪要（`conversations` 最新一版）；
    - 相关记忆（`MemoryStore.recall`，最多 8 条）；
    - 性格：hello 自己的角色，用无限的说话方式；说话人如果认得出，加上库里这个人的人物卡和 `active` 的性格条目（`library.person`）；
    - 最近 8 轮对话（新集合 `chat_turns`）。
  - **回答**：
    - 用测出来最快的模型，不用 JSON schema，直接要 1–2 句纯文字，桌宠口吻；不长篇大论，不说"作为 AI"。
    - 一轮最多大约 60 字，超时 6 秒。
    - 用无限的声音，走对话自己的说话通道。这条通道不受脱口秀 `only_talk` 限制，但嘴必须是 TTS，进入别的模式时要停下。
  - **记录**：每一轮写一条 `chat_turns`，包含：
    - 听到的话、回答；
    - 是否过滤、过滤原因；
    - 用的模型、费用；
    - 各段耗时：ear、通知 mind、读上下文、模型、合成、开口。
  - **花钱**：计费不拦（主人已定）。对话只在 `chat` 模式里跑；离开时停掉正在说的那句、把循环关掉。
- **网页**：在对话模式里，如果 hello 的听觉没开，模式条旁边提示"对话要先开听觉"。下一版让 hello 进对话模式时自动打开听觉。
- **模型测试**（和写代码同时做）：拿最近真实的几段话和上下文离线重放，比较 haiku、luna、terra 的首字时间、总时间、费用和回答质量。不写库，不播放。把对比结果给主人看，主人定。

## 不在这一版

- 流式模型和流式合成（目标 2.2–2.8 秒开口）；
- 说"hello"打断（要改固件）；
- 回声消除；
- MCP 和搜索；
- 进对话模式时自动打开听觉；
- 对话模式下单击 = 停。
