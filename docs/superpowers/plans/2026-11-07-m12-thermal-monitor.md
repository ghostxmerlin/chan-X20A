# M12 与温度监控 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans: root implements, one independent reviewer checks the completed change.

**Goal:** 将 M12 与 ASR 分开，展示 M12 检测效果/实际更新率，并标记两台设备的真实温度来源。

**Architecture:** 网页继续只读。M12 检测框与结果计数来自 StackChan 既有串口遥测，五秒滑窗计算实际结果更新率；不能把它称为视频帧率。StackChan 固件增加 ESP32-S3 芯片温度 1Hz 采集和只读遥测。M12 温度/原始视频需独立网络连接。

**Tech Stack:** 现有 Node 24 / Canvas / ESP-IDF 5.5.4 / C++，不升级依赖。

**Spec:** 用户明确要求拆分 M12/ASR、重点温度、检测效果/帧率、StackChan 温度；检查局域网未发现 M12 后，用户选择稍后接 M12 USB，先完成当前可做部分。

## Constraints and decisions

- 当前可交付 M12 检测框示意，不冒充 M12 原始画面，也不叠加到机身镜头；标注 640×480 坐标。
- M12 温度明确显示“未接入 M12 网络”，不使用历史 88–90°C 或伪造温度；网络/原始视频接入等待用户物理连接。
- 结果更新率按设备计数与时间戳计算五秒滑窗，至少 1 秒样本；待机/切换/重启/断线清空旧检测框和频率。不从网页轮询次数推算检测 FPS。
- StackChan 标注 ESP32-S3 芯片温度（不是室温/外壳温度），20–100°C 配置范围，读取失败/超过 3 秒标记无效，JSON 数值为 null。
- 固件 0.4.18 仅增加采集；M12 的 ASR 开关、舵机/保存角度、基本 UI 和关闭的功能不改变。
- 已有 AGENTS 授权开发机刷写；部署前核对身份/真实分区/当前版本/活动 ota_1、备份，仅写应用并独立验证。未通过任一前置检查不写入。

## Review focus

- 旧 M12 结果/旧计数不能在重新开启时变为新鲜状态；零人脸结果仍计入更新率。
- 不把低频 HTTP 轮询率当作设备检测率；counter reset、反向时间戳、重复样本和数据中断有界处理。
- 温度失败不回退为零或旧值；传感器只由单任务调用，旧 Android 可忽略新增字段。
- 页面故障与串口静默/待机分开；无网络时不可宣称已取得 M12 温度/原始画面。
- 刷写仅目标 ota_1，保持 NVS/资产/bootloader/otadata。
