# eye：每分钟用 haiku 看一次画面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 视觉开到"识别"档后，新的服务单元 `soul-eye` 每分钟取这一分钟服务器收到的画面（最多 6 张），连同 M12 事件一起交给 `claude-haiku-5-5`，得出这一分钟的视觉结果：几个人、各是谁、在哪、在做什么、画面环境、有什么变化。结果写进 `hello.eye_minutes`；情景页显示最新结果；开关条上的"识别"可以点了；花费那一行算上视觉识别。

**Architecture:**
- eye 的代码放在 `server/mind/` 包里：`eye.py` 负责处理一分钟，`eye_runner.py` 负责循环。这样能共用 `llm.chat`、`Store.put_run` 和花费统计、设置、记录读取，也随 mind 一起部署。
- 运行时是**另一个单元** `soul-eye`，和 `soul-mind` 互不影响。
- 开关是 `hello.switches.eye`，沿用总设计第 3 节的约定。
- 页面经过 mind 接口读结果，这是 Mac 唯一能到的通道。

**Tech Stack:** Python 3.11 + pymongo；Node 24；aihubmix `/chat/completions`，`response_format: json_schema` 严格模式（比拼时 haiku 24/24 合格）。

**Spec:** `docs/superpowers/specs/2026-11-11-senses-split-design.md`（第 2 节第 4 条、第 3 节、第 4 节第 3 步）。

## Global Constraints

- 模型 `claude-haiku-5-5`，价格每百万 token 0.1 / 0.5 美元（aihubmix 公开价，2026-11-11），写进 `llm.PRICES`。单次超时 90 秒；失败重试 1 次；再失败就记"失败"，并按 1、2、5、10 分钟退避。
- 只有 `switches.eye.on` 为真才调用。**这一分钟没有画面就不调用**：画面只在有变化时上传，没有画面就说明没变化，或者摄像头关着。
- 处理时机：分钟结束后满 15 秒，再处理这一分钟。每分钟只处理一次（游标存在 `hello.eye_state`）。停机后重新开始时，**只补最近 10 分钟**，不补更早的，避免一口气花钱。
- 每分钟最多送 6 张图；多于 6 张时按时间均匀取 6 张。文件路径必须在 `recordings` 根目录内，不在的、或者文件缺失的就跳过。
- 提示要说清楚：
  - M12 的 `persons` 也包括近处的人，**不能写成"远处人形"**（比拼时的教训）。
  - M12 认出的名字可信，`me` 就是主人，用设置里当天的主人称呼。
  - 没认出的脸写"未认出的人"。年龄、性别不可靠，不要写。
  - 用最可能的正向说法。
- 每日花费和 mind 共用一个上限 `settings.budget_usd_per_day`（`Store.cost_today` 已经把 `mind_runs` 里所有步骤都算进去了）。超过上限的分钟记 `budget`，不调用。
- 运行记录写进 `mind_runs`，`step: "eye"`，`/stats` 会自动按步骤统计。
- 状态文档 `switches.eye_status {running, available, at}`，每 30 秒写一次。`available` 的意思是"环境文件里有 API_KEY"。
- 部署要用户明确说"部署"。eye 开关默认关。

## Review Focus

1. **识别开着，但摄像头关着**：没有画面，就不调用，费用为 0。测试在 Task 1。
2. **停了几个小时后重新开**：最多补 10 分钟，不调用更早的分钟。测试在 Task 2。
3. **模型返回的不是 JSON，或者缺字段**：重试 1 次，再失败就记失败、开始退避，下一分钟不会被打满调用。测试在 Task 1。
4. **画面文件缺失，或者路径越界**：跳过这张；这一分钟一张能读的都没有时，就不调用。测试在 Task 1。
5. **eye 的状态过期**（服务停了）：页面写"识别状态未知"，不能写成不花钱。测试在 Task 4。

### Task 1: `eye.py`：处理一分钟

**Files:**
- Create: `server/mind/eye.py`
- Modify: `server/mind/llm.py`（`PRICES` 加 `"claude-haiku-5-5": (0.1, 0.5)`）
- Test: `tests/test_mind_eye.py`（用 `mind_fixtures.FakeDB`、`test_mind_fusion.FakeChat`、临时目录当 recordings 根目录）

**Interfaces:**
- Produces:
  - `EYE_MODEL = "claude-haiku-5-5"`、`EYE_PROMPT = "eye-v1"`、`EYE_SCHEMA`。`EYE_SCHEMA` 就是比拼用的那套字段：`people_count, people[{who,where,doing}], activity, scene, changes, confidence(high/mid/low)`。
  - `CHAT = llm.chat`，测试里可以替换。
  - `minute_inputs(db, recordings_root, minute_ms) -> {"frames": [{"seq","session","at","path","b64"}], "events": [str], "skipped": int}`：
    - 帧取 `at ∈ [minute, minute+60 s)`，最多 6 张，按时间均匀取。
    - M12 事件从 `hello.vision` 取同一分钟的：`face_found/lost/named`、`person_*`、`vision_on/off`。每条写成一行，格式 `"HH:MM:SS 脸#4 出现"` / `"… 认出 主人"` / `"… 人形#2 出现"`，最多 40 行。
  - `run_minute(env, store, s, minute_ms, recordings_root, now_ms) -> dict | None`：
    - 这一分钟没有可读的帧时返回 `None`，什么都不写。
    - 否则按以下情况写 `eye_minutes` 并返回：
      - 预算用完：`source: "budget"`，不调用；
      - 退避中：`source: "backoff"`，不调用；
      - 调用成功：`source: "model"`，带 `result`；
      - 两次都失败：`source: "failed"`，带 `error`。
    - 每条记录带上 `minute`、`frames`（seq 和 path，不存 b64）、`events_n`、`run_id`、`prompt`、`model`、`at`。
  - 退避状态记在 `db["eye_state"]` 的 `{_id:"live"}`：`failures`、`backoff_until`，规则和 `fusion.BACKOFF_MIN` 一样。
  - 消息格式：
    - system 是提示词；
    - user 的 content 先放一段文字：时间、主人称呼、M12 事件各行、上一分钟的 eye 结果摘要（没有就不写）；
    - 然后每张图一个 `image_url`，值是 `data:image/jpeg;base64,…`。

- [ ] **Step 1: 写失败的测试**
  - `test_no_frames_no_call_no_record`
  - `test_frames_call_once_with_images_and_m12_lines`：3 张帧、2 条事件。断言：调用 1 次；`content` 里 `image_url` 有 3 个；文字里有 `"认出 主人"`、没有 `"远处"`；`response_format.json_schema.strict` 为真；`eye_minutes` 一条，`source == "model"`；`mind_runs` 一条，`step == "eye"`，`cost_usd == llm.cost_usd("claude-haiku-5-5", usage)`。

### Task 2: `eye_runner.py` 循环与 `soul-eye` 单元

**Files:**
- Create: `server/mind/eye_runner.py`
- Modify: `server/mind/remote_setup.sh`（建立并重启第二个单元 `soul-eye`，参数和 mind 一样，命令改成 `-m mind.eye_runner`）、`server/mind/deploy.sh`（说明里加上会重启 soul-eye）
- Test: `tests/test_mind_eye.py`

**Interfaces:**
- Consumes: Task 1 的 `run_minute`。
- Produces:
  - `tick(db, store, s, env, recordings_root, now_ms) -> list[int]`：返回这次处理掉的分钟。
    - 开关关着时，只把游标推进到已经可以处理的那一分钟，不处理任何分钟（以后打开也不回补关着那段）。
    - 开关开着时，处理游标之后、`<= floor(now − 60 s − 15 s)` 的分钟，**最多最近 10 分钟**。
    - 游标存在 `eye_state.cursor_minute`。
  - `write_status(db, on, available, now_ms)`：写 `switches.eye_status`。
  - `main()`：命令行参数和 `mind.runner` 相同（`--hubmix-env`、`--settings`、`--recordings`）。每 5 秒执行一次 tick，每 30 秒写一次状态。启动时打印 `eye: switch on|off`，开关变化时也打印。
