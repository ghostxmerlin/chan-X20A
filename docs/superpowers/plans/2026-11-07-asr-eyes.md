# 本体眼睛、Wi-Fi 资源安装与 ASR 台词表情实施计划

> 使用 `superpowers:executing-plans` 在本会话连续实施，末尾一次独立整体验证；不为 routine 实现选择再次等待授权。

**Goal:** 接入现有三款/30状态眼睛播放器；不用拔卡，通过鉴权 Wi-Fi 安装90段资源；ASR open实际开始播放40条台词之一时配上近似表情。

**Architecture:** 单一板级SD owner使用SPI3与LCD共存，后台加载/校验/解码，LVGL只交接完整RGB565缓冲。公共服务统一配置、播放、停止、去重、页面取消和Voice条件取消。网页提供手动控制；安装脚本只上传固件白名单里的既有资源。

**Tech Stack:** 固定 ESP-IDF5.5.4 / LVGL9.4.0 / esp_lvgl_port2.7.2，现有SOULAN1解码器，C++17、Node、本地Python资源生成。无依赖升级。

**Spec:** [assets/immplement.md](../../../assets/immplement.md)，以及用户本轮明确新增的ASR联动和不拔卡Wi-Fi安装要求。原草案“仅文档/不联动/不上传”限制由最新用户要求覆盖。

## 固定边界与实施判断

- 保留分区、NVS、保存角10°、遥控上下屏蔽、左右/中心、ASR爱心叉号、M12手动模式。眼睛不驱动舵机、不做感知或M12自动唤醒。
- 三款v05/v14/v18，30状态；文件白名单、大小、SHA256和帧CRC一致。未就绪保持旧首页，声音照常播放。
- 启动旧首页；首次ASR成功起声可自动启用默认v05并在结束后保留idle。网页明确关闭后尊重关闭意图，后续ASR不擅自启用。配置只在RAM，不切页/亮屏；页面/旧反馈 > Manual > Voice > idle。
- 所有40条使用PLAY编号重新建立近似映射，不把旧QT的300条候选编号当实际声音。网页点播声音不自动触发表情；ASR播放失败、忙时丢弃或等待800ms期间不启动表情。
- 本地固定IDF5.5.4官方SPI LCD驱动已经在每次事务pre回调使能DC输出、post回调关闭输出；SDSPI命令和LCD共用SPI host的独占事务仲裁。采用这条已存在的全事务/DMA串行链，避免再造会嵌套死锁的SPI锁；增加构建检查固定该依赖契约。先在核1初始化带MISO35的SPI3、CS3/4高，再挂载SD，再初始化LCD。不手工切换驱动中的GPIO、不卸载LCD SPI。
- SD挂载仅开机一次，不格式化、不热插拔自动重挂；单次命令有界。FATFS开启heap长文件名以容纳原资源名。文件访问由存储层串行、每4KiB让出任务；LCD靠同host原生事务链交错。
- 2×256KiB压缩槽、2×153600字节RGB565帧、4096字节scratch；后台不持LVGL锁。READY帧带generation；LVGL换源后旧缓冲RETIRING，REFR_READY才复用。隐藏取消不等待后续刷新，已绑定帧继续保留到安全交接。
- 1500ms首帧期限、loop1000–30000ms、16条/60秒请求去重。未知结果不重发。GET状态与遥测同一快照，提交/渲染序号不冒充物理显示。
- 新增安装入口只接收固件内白名单资产，绑定boot、大小和SHA256；有界接收后写`.part`，校验后原子改名。相同文件跳过，旧不同内容保留一次`.prev`且不覆盖已有备份；无任意路径、URL、格式化或通用文件管理。

## Review Focus

1. LCD DMA与SD交替、GPIO35释放、无卡或坏卡仍启动原首页。
2. 取消/停屏/切页/旧反馈时未完成的SD加载或解码永不复活。
3. LVGL仍引用旧帧时不写该缓冲，熄屏无后续刷新时可及时取消。
4. ASR起声后才触发，音频收尾只取消自己持有的Voice效果，不能覆盖后来Manual。
5. 重复UUID/不同正文、旧boot、上传中断/坏哈希不重复播放、不损坏旧资产。
