## 0. 先说结论

1. **模式 = 一个有名字的"状态"，规定 hello 此刻长什么样、每个输入是什么意思、可以花什么钱。** 同一时刻只有一个模式（严格互斥，【用户定】）。模式本身不管感官开关；感官和花钱由另外两层管（第 3.3 节）。
2. **八个模式**【补充】：脱口秀（默认）、对话、设置、事件驱动、字幕（两个方向）、围观、陪伴、IDLE。三个特殊的：**设置**是临时层，关掉回到原来的模式【我定，沿用第一版】；**事件驱动**是外面一层，由它去进别的模式【主人 2026-11-14】；**IDLE** 是"关掉一个模式之后、没有别的模式"的状态【主人 2026-11-14】。
3. **唯一的真相在服务器（mind）**：mind 存当前模式、改模式、记日志；机器人、DualKey、页面只上报输入、只显示 mind 确认过的模式。机器人上的眼睛、角标、触摸含义都由 mind 下发的"模式快照"决定。
4. **前置工作：一条服务器到机器人的常连下行。** 今天服务器没有办法主动告诉机器人任何事（`/mouth` 只是 ear 原样转给 soul-tts，`server/ear/mouth_link.py:1-7`；机器人只认 `hello` 和 `tts.*` 消息，`fw/mouth_link.cpp:52-73`）。采用 DualKey 设计已定的做法：**ear 自己终结 `/mouth`**。这是风险最大的一块，先单独做成一个"行为不变"的改动、单独上线验证，再在上面加模式消息（第 4.3 节）。
5. **花钱分三层**：计费总闸（下滑快捷设置页上的"计费开关"）> 各感官开关（今天就有）> 模式自己的花钱行为（脱口秀的说一轮、提前写、连续说）。第一步的总闸 = "关掉所有付费开关，并且关着时不许再打开"；进程级的模型调用闸门放到后一步。离开脱口秀时它的花钱行为全部停。**第一步里进入任何模式都不会自己开始花钱**，IDLE 和开机也不动付费感官【主人 2026-11-14】。
6. **第一步只做框架**：模式状态、切换、同步、每个模式的眼睛和角标、上滑模式页、下滑快捷设置页、左滑状态摘要、页面模式条、计费总闸和预设的服务器那一半。脱口秀 = 今天的行为；IDLE 有自己的屏幕；其余六个模式是空壳（能进、能出、有眼睛和角标，没有内容）。

### 1.1 读法

- **"joy stick" 是 DualKey 的摇杆，不是官方遥控器的摇杆。** 依据：第一版"用户的回答"一节里主人说"摇杆指 DualKey 的摇杆"（`2026-11-13-hello-modes-design.md:30`）；DualKey 设计里主人的原话"joystick，上下左右推时，我们分别入 4 种不同的模式"（`2026-11-13-remote-emotion-dualkey-design.md:257`，同文件 `:274`）。官方遥控器的摇杆另有用途：今天是四个开关（`fw/interaction.cpp:91-94`），以后开机默认层是情绪锚点（DualKey 设计 0 节第 5 条）。补充没有给官方遥控器派模式用途，第一步不动它。
- **每对口令**：前一个进入，后一个离开【用户定】。forward = 进入脱口秀、backward = 离开脱口秀（→ IDLE）；新的口令分配直接取代旧的，第一版的"backward = 停"和"不在脱口秀时 forward 直接说一轮"作废【主人 2026-11-14】。被取代的旧分配列在第 5.1 节。
- **事件驱动是外面一层**【主人 2026-11-14】：补充里事件驱动的单击"取决于进入了什么模式"，主人确认它会自己进出别的模式。
- **IDLE**：关掉一个模式以后去 IDLE；如果指令直接打开下一个模式，就直接进那个模式，不经过 IDLE【主人 2026-11-14】。预设 4 也能直接进 IDLE【补充】。
- **字幕的两个方向**是同一个模式的两个方向（中音英字 = 听中文、出英文字幕；英音中字反过来）【补充】。
- **双击那一行**：我按顺序填给脱口秀、对话、围观、陪伴、字幕、IDLE，事件驱动空着：它没有自己的触摸，跟着它进入的模式走【我定，和第 1.2 节第 11 条一致】。
- **"快捷数字设定"**：一组 0–9 的预设，是改开关的快捷方式，不是模式（4 除外）。第一版里主人说过"会另外规划一组 ASR 0–9 的设置口令"，这就是那一组。入口是 ASR 数字词，也放在下滑快捷设置页和网页上【我定】。

## 3. 模式的概念

### 3.1 一个模式由什么组成

一个模式是服务器模式表（`server/mind/mode_table.py` 的 `MODES`，公开仓库里只放这张表，不放人名）里的一行：

| 字段 | 意思 | 例子（脱口秀） |
|---|---|---|
| `id` | 英文名，各处通用 | `talk` |
| 中文名、角标文字、颜色 | 人看的；角标第一步用 ASCII（`label`） | 脱口秀、`TALK`、洋红 |
| `look` | 机器人屏幕长什么样：眼睛款式或专用页、自然循环用哪组表情 | 笑面男 |
| `touch` | 首页单击、双击的意思 | 单击 = 说一轮；双击 = 开提前写 |
| `inputs` | 在这个模式里各输入的意思（ASR、DualKey 点击） | forward = 说一轮 |
| `paid` | 这个模式**可以**有的花钱行为 | 说一轮、提前写、连续说 |
| `enter` / `leave` | 进入、离开时做的事 | 离开：关提前写、关连续说、停 TTS |
| `kind` | 普通 / 临时层 / 外层 / 空闲 | 普通 |

模式**不**包括：感官开关（听觉档、视觉档、情景、纪要）、嘴的档位、音量、追踪和转头。这些照旧独立，有自己的开关和显示。以后某个模式要"进入时自动开它要的付费感官"（主人 11-13 的回答），也写在 `enter` 里；第一步不做，主人 11-14 也定了 IDLE 和开机时先不动它们。

### 3.3 三层：计费总闸、感官开关、模式

| 层 | 管什么 | 在哪改 | 关着时 |
|---|---|---|---|
| 计费总闸 | 所有花钱的东西 | 下滑快捷设置页、页面、预设 0 / 9 | 付费的开关全关；关着时不能再打开；说话类接口都拒绝 |
| 感官开关（已有） | 听觉档（关 / 本地 / 听悟）、视觉档（关 / 上传 / 识别）、情景、纪要、嘴 | 页面开关条、预设 | 各自停 |
| 模式 | 模式自己的花钱行为（第一步只有脱口秀：说一轮、提前写、连续说） | 切模式 | 不在这个模式里就不跑 |

- **"关"就是不花钱**（主人的规则"no cost when off"）。总闸关 = 现在不花任何钱，而且机器人、页面、DualKey 都看得见：总闸每变一次，模式快照的 `seq` 加 1 并推下去（第 4.1 节）。
- **第一步的总闸**只用"关掉 + 禁止再开"：关掉听悟、识别、纪要、情景（记忆学习跟着停，`memory_worker.py:134`）、提前写、连续说，停正在说的；关着时这些开关和说话类接口都返回"计费关着"。这已经覆盖今天所有会自己花钱的后台；剩下的缺口是命令行一次性工具（`probe.py`、`runner.py --rebuild --fusion`），第一步写进说明。
- **后一步再加的加固**（第 10 节）：在 `llm.chat` 一处拦所有模型调用；在 TTS 的 `TtsHttp.say`（`speak.py:577`）也查一次；各后台循环开头先查总闸，免得被拒的调用被当成"模型出错"写进 `mind_runs`、触发退避（`model_calls.py:42`，`eye_runner.py:47-56`，`memory_worker.py`）；总闸读取要"缓存过期先重读、重读失败才算关"，不能按"上次成功读取超过 60 秒就关"，否则每分钟才调一次的 eye、纪要会永远被关。
- 总闸打开**不会**恢复任何东西，只是允许再打开；"全开"用预设 9。
- **第一步进入模式不开任何付费感官；IDLE 和开机也不动付费的听觉、视觉，先手动**【主人 2026-11-14】。

### 3.4 严格互斥，加两个特殊层

- **严格互斥**【用户定】："先做严格互斥，之后再融合"。同一时刻只有一个模式说了算。
- **设置是临时层**（第一版 3.2，保留，【我定】）：open 进入时记下原来的模式；close、5 分钟没有动作，回原来的模式；在设置里直接打开别的模式，就进那个模式。
- **事件驱动是外面一层**【主人 2026-11-14】：start 进入"事件驱动·等待"；以后它按事件自动进入一个"客人模式"（例如看到一群人进围观），客人模式离开时回到"事件驱动·等待"，而不是 IDLE；stop 离开事件驱动，回 IDLE。主人在事件驱动开着时手动选了一个模式：事件驱动停，直接进那个模式【主人 2026-11-14】。"事件驱动·等待"时屏幕和 IDLE 一样，角标写 `AUTO`【我定】。
- **IDLE 是"什么都没在跑"**：不是任何模式的内容。屏幕安静；单击看 badge；双击以后放音乐。

### 3.6 开机、服务重启、断线

- **机器人开机（新的 boot_id）**：mind 把模式设成脱口秀（"默认模式"【补充】），记一条 `by: boot`，不论开机前是什么模式。开机不动付费感官【主人 2026-11-14】；提前写、连续说关掉（mind 一直在、本来就在脱口秀时也一样，见 3.8），所以开机进脱口秀不花钱。
- **mind 重启**：从数据库读回当前模式和 `seq`，不改；提前写、连续说照今天的规则回到关。ear 重启：机器人重连 `/mouth` 后马上收到当前模式。
- **机器人和服务器断开**（`/mouth` 没连上）：机器人保持最后一次的样子，角标变灰、加 `OFF`；模式口令、上滑页、触摸里需要服务器的动作都不执行，屏幕提示 `OFFLINE`；本地的东西照常（转头词、追踪、音量、快捷设置页的音量、badge 页）。
- **服务器一侧**：机器人离线时模式照常可以在页面上改，页面写明"机器人离线，连上后会照这个显示"。

### 3.8 边界情况（模拟页发现的，【我定】）

| 情况 | 怎么做 | 理由 |
|---|---|---|
| 单击是"无"的模式（字幕、设置、事件驱动·等待）里点屏幕 | 机器人本地提示 `NO TAP`，不发服务器；同样的模式里 DualKey 单击到了服务器，结果 `no_action`，什么都不做 | 没有动作的输入不必绕服务器一圈；DualKey 的点击只能经服务器 |
| 对话、围观、陪伴（空壳）里单击 | hello 正在说话 → 停；否则结果 `not_implemented` | 补充写的是"停"；第一步这些模式里不会说话，"停"只防残留 |
| IDLE 里 DualKey 单击 | `no_action`（不翻 badge） | badge 是机器人本地的一页，第一步没有下发"翻页"的消息；屏幕单击照样翻 |
| 事件驱动托管着客人模式时说 stop | 事件驱动和客人模式一起停，→ IDLE | stop 是"离开事件驱动"，客人模式属于它 |
| 事件驱动开着时说 open（进设置） | 算手动选模式：事件驱动停；设置记下的"原来的模式"= 当时显示的那个（客人模式，不再托管；还在等待时就是 IDLE） | 主人第 12 条：手动选模式就停事件驱动；close 不能把事件驱动又开回来 |
| 离开设置（不论 close、超时、直接打开别的模式、DualKey、长按、预设 4、开机） | "原来的模式"一律清掉 | 它只在设置里有意义，留着会让下次 close 回错地方 |
| 机器人重启，mind 一直在、本来就在脱口秀 | 模式仍是脱口秀；**提前写、连续说关掉、正在说的停**，和从别的模式回来一样；付费感官不动（主人第 3 条） | 和"服务重启后提前写、连续说回到关"一致，开机不花钱 |
| 在上滑页或网页上点当前模式 | 两处都 = 离开（→ IDLE） | 一个规则，两处一样 |
| 页面按预设 1 / 9 时机器人不在线 | 服务器那一半照做；页面照实写机器人那一半哪一步没成，不排队、不重试 | 第一步机器人那一半只由页面直接发，没有地方替它记着 |

## 4. 唯一的真相和同步

### 4.1 谁存、谁改、谁显示

```
  机器人（ASR、触摸、上滑页、快捷设置页）──输入──▶ ear ──▶ mind（存、改、记日志）
  DualKey（方向、点击）────────────────输入──▶ ear ──▶ mind
  页面（模式条、快捷设置）──────────────输入──────────▶ mind
  mind ──快照──▶ ear ──▶ 机器人（眼睛、角标、触摸含义）
                    └──▶ DualKey（摇杆灯）
  页面 ◀──每 2 秒读快照── mind
```

- **mind 是唯一能改模式的地方。** 当前模式存在 `hello.mode`（一份文档 `_id: current`），每次改动另记 `hello.mode_log`（永久保留）。所有改动在 mind 里排队、一个一个处理。
- **`seq`**：模式变了、计费总闸变了，都加 1；页面、ear、机器人都只看 `seq`。机器人对**相同**的 `seq` 当作没变化（不算坏消息）；`/mouth` 每次握手后的第一条快照无论 `seq` 大小都收下（防 mind 的 `seq` 被重置后机器人拒收到重启）。
- **输入按到达 mind 的先后处理，最后一次赢。** 设备的输入带 `device + boot + seq`，按这三项去重，做法和主人信号一样（`server/mind/owner_signals.py:40-44`）。设备上按下超过 3 秒才到的输入丢掉【我定】，**DualKey 也一样**：DualKey 重连后重发攒下的信号，打分照收，但方向和点击超过 3 秒就不切模式，免得突然连切几次。
- **快照**是机器人显示需要的全部：模式、方向、外层状态、计费总闸、`look`、`touch`、`seq`。外观写在快照里而不是固件里，以后换某个模式的眼睛不用刷机；固件只认一组固定的词（三款眼睛、笑面男、字幕页、参数页、IDLE 页），不认识的就保持原样。
- **机器人显示完回一条"已显示 seq"。** 页面据此写"机器人已显示 / 等机器人 / 机器人离线"。ear 给每条 `/mouth` 连接一个编号，mind 只认最新一条连接的"已显示 / 断开"（ear 允许两条同时在，`ear_server.py:965`，旧连接晚到的"断开"不能把新连接标成离线）。

### 4.2 多快

- 机器人自己的输入：mind 处理完直接在回复里带新快照，ear 立刻转给机器人。目标 1 秒内换角标【我定，网络正常时】。
- 页面、DualKey 的输入、计费总闸：ear 每 1 秒在本机回环上问一次 mind 的当前 `seq`，变了就推快照。目标 2 秒内【我定】。（今天 ear 读开关是 5 秒一次，`ear_server.py:953`，模式需要更快。）
- 另外每 60 秒重推一次（相同 `seq`，机器人当作没变化），并在机器人连上 `/mouth` 时马上推一次。

### 4.3 下行通道：ear 自己终结 `/mouth`

第一版留了"甲：ear 终结 `/mouth`"和"乙：新开一条连接"两种；DualKey 设计后来定了甲（DualKey 设计 0 节第 3 条），这里照甲做，分两步上线。

**第一步：终结本身，行为不变**（不加任何模式消息，先在 0.4.91 上验证）：
- ear 自己回机器人的 `hello`（opus、60 ms、24 kHz，机器人按这三项检查，`fw/mouth_link.cpp:60-61`）。
- 机器人连上时 ear 才连 soul-tts（把机器人的原始 `hello` 转给它，吞掉它回的 `hello`）；**机器人一断开就关上游**，保持今天"没有设备就不合成、不花钱"的语义（`speak.py:566-567`）。
- soul-tts 中途断开：ear 记着正在播的流编号（看 `tts.start` / `tts.end`），**立刻给机器人发 `tts.stop`**，代替今天"断线清流"的作用（`fw/mouth_link.cpp:93-97`），否则机器人会以为还在播，ear 也会一直给听觉喂静音（`ear_server.py:526-556`）。DualKey 设计也写了这一条（`2026-11-13-remote-emotion-dualkey-design.md:216`）。然后每 5 秒重连上游，重连后重放机器人的 `hello`。**机器人这一侧不断。**
- 其余帧（二进制音频、`tts.*` 文本、机器人的播放回报）双向原样转发。

**第二步：模式消息**（在第一步验证过之后）：
- 机器人的新消息 `mode_input`、`mode_applied` 由 ear 交给 mind，不转给 soul-tts。
- ear 在这条连接上发 `mode`（快照）和 `mode_result`（对机器人那次输入的答复，带一句 ASCII 屏幕提示）。
- 第一步**不**下发本体控制（`control`）：预设的"机器人那一半"推到后一步（第 7 节、第 10 节）。机器人现有的控制 worker 一次只收一条（第 2.4 节），要先改。

ear 每次改动要重启，重启会断一次听觉（第一版 8.1）；部署挑没人用的时候。消息格式见计划的"接口"一节；单条不超过 1 KB【我定】（机器人在 `/mouth` 上收的单条消息上限是 1600 字节，`fw/mouth_stream.h:19`）。

### 4.4 DualKey

- DualKey 的 `mode {direction}` 和 `click {type}` 今天已经经 ear `/signal` 存进 `hello.owner_signals`（`owner_signals.py:64-70`）。第一步：mind 存好信号后，按模式表把它当成一个模式输入处理（带上信号的 `age_ms`，超过 3 秒不切），结果写进信号的 `result`（DualKey 设计 C.1 已经留了这个字段）。这就是 DualKey 设计 C.5"绑定表"里 `dualkey.*` 那几行，由模式表接管。
- 快照变了，ear 给连着的 DualKey 发 `{"type":"mode","current":"<id>"}`，摇杆灯随之变色；`idle` 关灯（`dualkey/README.md:63`）。

## 6. 屏幕

- **角标**：右上角一块颜色底 + 快照里的 ASCII `label`（例如 `TALK`、`SUB ZH>EN`），所有页面可见，关屏时隐藏；在 DualKey 设计的顶部情绪条（320×3）下面，不重叠（DualKey 设计 A.3.5）。离线时变灰并加 `OFF`。事件驱动托管时，角标旁加小 `A`；事件驱动开着、还没进入任何模式时，显示 IDLE 的屏幕，角标写 `AUTO`【我定】。
- **切换时**：整屏中间用大号 ASCII 显示 `label` 约 1 秒。不出声（不花钱，也不让麦克风收进去）【我定】。
- **上滑：模式选择页**：3×3 九格（脱口秀、对话、设置、事件驱动、字幕中→英、字幕英→中、围观、陪伴、IDLE），当前模式高亮，**再点当前格 = 离开**（和页面一致）；点一格就发给服务器，格子显示 `...` 直到新快照到；离线时整页灰、写 `OFFLINE`。点空白或下滑关闭。
- **下滑：快捷设置页**：
  - 音量：−、＋（本地直接改，存 NVS，和音量口令同一个设置，`fw/volume_setting.h:6-12`）；
  - 计费：开 / 关（发给服务器，显示以快照为准）；
  - 0–9 十个预设键（发给服务器；5–8 灰）。
  - 上滑或点空白关闭。
- **左滑：状态摘要页**：今天的摘要页，加两行：当前模式、计费总闸。
- **每个模式的屏幕身份**见第 3.2 节表。字幕页、参数页、IDLE 页第一步都是占位：字幕页写方向，参数页列当前数值（只读），IDLE 页黑底小字 hello，badge 页大字 hello 和固件版本【我定】。
- **文字**：第一步全部用现有 ASCII 字体。中文字库（主人已定用思源编进固件）推到字幕那一步一起做；那时角标改成一个中文字，缺字时仍退回 `label`。
- **省内存**（主人的规则：PSRAM 优先）：模式页和快捷设置页用时才建、关了就删；状态和输入队列放 PSRAM；上线前后比内部 RAM 剩余、最大连续块、DMA 剩余。

## 7. 快捷设置和 0–9 预设

预设是"一次改一组开关"，分**服务器那一半**（付费开关、计费总闸、模式）和**机器人那一半**（本地听觉、视觉上传）。两半都写在 `server/mind/mode_table.py` 的 `PRESETS` 里，定义只有一处。预设按字面【主人 2026-11-14】：

| 键 | 名字 | 服务器那一半 | 机器人那一半 |
|---|---|---|---|
| 0 | 花费全关 | 计费总闸关：听悟、识别、情景、纪要、提前写、连续说全关；正在说的停 | 不动（本地听觉和视觉上传不花钱） |
| 1 | 数据收集 | 同 0：**计费总闸关**，所有付费的关（不花钱） | 听觉开（本地档）、视觉"上传"档。"情绪感知"没有单独的开关：本地听觉每句话都带 SenseVoice 的情绪标签（机器人按它出表情，`fw/eye_mode.h:18-30`），听觉开着就有【我定】 |
| 2 | 听悟反转 | 听悟开关反转；总闸关着时不能开，提示"计费关着" | 不动 |
| 3 | 提前写反转 | 提前写反转；只在脱口秀里有效 | 不动 |
| 4 | IDLE | 进入 IDLE | 不动 |
| 5–8 | 空（5 也空着：听觉先手动【主人 2026-11-14】） | 只记日志，提示"未定义" | — |
| 9 | 花费全开 | 计费总闸开；听悟、识别、情景、纪要开；嘴切到 TTS；在脱口秀里时提前写、连续说也开（不在脱口秀时这两项跳过，提示一句）【我定，按"字面"读】 | 听觉开、视觉"上传"档 |

- **第一步里机器人那一半只有页面能执行**：页面已经能直接控制机器人（和开关条"本地"听觉档、"上传"视觉档发的是同一组请求，`switches-ui.js:75-89`），所以从页面按 1 / 9 是完整的；从机器人（数字词、快捷设置页）按 1 / 9 只做服务器那一半，屏幕提示 `SENSES: USE PAGE`。机器人那一半经 `/mouth` 下发放到后一步（第 10 节）。
- 页面执行机器人那一半时任何一步失败（例如 M12 不在），页面照实写哪一步没成，不写"成功"。
- 说过 0 以后，用声音能重新开闸的只有 9；2 在总闸关着时会被拒。
- 数字词说出就生效，屏幕显示 `PRESET N`，页面记一条【我定】。误识别的代价：9 每小时约 1.3 元（第一版 2.6），屏幕和页面都看得见，说 0 就停。
- 预设不改当前模式（4 除外）。
