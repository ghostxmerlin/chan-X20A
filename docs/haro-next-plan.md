# 情绪宝宝下一阶段实施计划

规划日期：2026-10-30。**本计划不在今晚实施；先完成并验收 Android 观察与记录链路。**
今晚继续保持机器人静音、舵机静止；以下声音、动作与模型接入均为未来迭代。

## 路线与可复用基础

保留固定版本的 ESP-IDF 5.5.4、官方板级驱动和原机备份，继续使用独立采集业务入口。
情绪宝宝建立自己的事件、状态和表现模块；不恢复官方云鉴权，也不重写已经验证的硬件驱动。
采集与情绪处理共用一次硬件读取，新增逻辑不得再独占麦克风、摄像头或阻塞采集任务。
采集能力与时间戳约束以 [Collector 协议](collector-protocol.md) 为准，验收入口见 [采集计划](collector-plan.md)。

已只读检查 `~/stick/research/haro-resource-kit-20261028/`：该目录没有 README，入口为 `START_HERE.txt`、`overview.txt`。
其中 `logic/controller.py` 是可运行离线原型，提供 idle/listening/thinking/speaking/sleep 会话状态。
它已有静音、离线、休眠、打断、事件冷却、过期 turn_id 拒绝和模型 JSON 校验。
它尚无真实采集、ASR/LLM/TTS 服务、硬件适配或持久心情；不能直接宣称接入即有情绪智能。
其 `ear_lift_once`、`slow_sway` 只是意图名，不能直接映射为 StackChan 舵机动作。
本轮没有修改 stick，也不运行其中任何硬件控制程序。

## 建议架构

| 层 | 责任与接口 | 首版位置 |
| --- | --- | --- |
| 采集 | camera/audio/sensors 单生产者，提供 boot_id、seq、设备时间和有效性；原始记录始终可用 | 机器人 Collector |
| 事件 | 将有效样本变成 touch_down、touch_hold、sound_activity、idle_timeout 等，带来源序号、时间和规则版本 | 先在 Android 离线回放中验证，再将简单规则移到机器人 |
| 持续状态 | 分开保存会话状态、机器人心情、静音/休眠标志；按事件和经过时间更新，输出原因 | 无硬件依赖的确定性模块 |
| 表现 | 从状态生成表情、短句、音效、动作意图，经优先级、冷却和适配器执行；回报完成/失败 | 先 App 预览，后机器人屏幕，再声音与动作 |

Android 仍是观察、记录、标注和调参端；简单触摸反应最终在机器人本地运行，断开手机也可体验。
较重的 ASR/LLM 推理后续放在 Android 或明确选择的服务端，模型只给受约束建议。
第一轮不引入第二个 `/v1/audio` 消费者：Android 内部分发已收到的 PCM 给录制和特征提取。
机器人本地特征直接订阅已有音频采集数据，不打开另一套 codec 读取循环。

## 最小可玩功能：摸摸会开心，安静会打盹

先用头顶触摸或 App 按钮触发：短触显示开心表情，持续触摸显示陪伴表情，闲置进入困倦表情。
App 提供“唤醒 / 休息 / 静音”和当前状态、触发原因；机器人先只做屏幕反馈。
以 30 秒无互动进入困倦、触摸冷却 800 ms 作为可调整的原型默认值，不作为已验证参数。
睡眠时抑制普通提醒；显式唤醒恢复活动；静音不停止采集，也不使记录丢失。
先实现 neutral/happy/curious/sleepy 四种原创屏幕表现，避免首轮同时扩展多种输出设备。
声音只产生“检测到声活动”等事件，不把音量大或人脸表情直接标成用户的真实情绪。

## 持续状态与事件记录

首版心情只描述机器人：`energy`、`affinity` 各为 0–100，另有当前 expression；更新规则可配置。
触摸小幅提高 affinity，长时间活动消耗 energy，休息恢复 energy；所有变量限幅并缓慢回归基线。
会话状态与心情相互独立：speaking 表示正在输出，不代表 happy；静音是正交标志。
短期会话状态不跨重启恢复；持久值带 schema_version，仅在状态变化后节流保存。
重启读取失败时回到明确默认值；离线经过时间没有可信时钟时不推算“睡了一夜”。
新增 `behavior_events.jsonl`、`behavior_state.jsonl`，关联原采集 boot_id/seq 和规则版本。
传感器 invalid、旧时间戳、采集 gap、boot_id 变化必须成为事件；不补造触摸或声活动。
模型或播放回调用 generation/turn_id 匹配当前请求，打断后到达的旧结果不再改变表现。
同一录制输入和同一配置应得到一致状态轨迹；用户标注与模型推测分别保存。

## 交付顺序与每步验收

| 顺序 | 具体交付 | 验收条件 |
| --- | --- | --- |
| H0：采集门槛 | 完成 Collector 三路记录、重连分段、导出和持续运行验证 | 先满足采集计划验收；新增情绪工作不能掩盖采集缺口 |
| H1：回放原型 | 从一次真实会话生成触摸/闲置事件；Android 展示状态与原因，支持按钮注入测试 | 相同输入重复回放结果一致；无效样本不触发；日志可定位到原样本 |
| H2：屏幕宝宝 | 机器人本地事件规则、四种表情、唤醒/休息/静音；保持静音和舵机静止 | 用户清醒时连续触摸测试；单次接触不过度重复；休眠/唤醒优先级正确；三路记录仍稳定 |
| H3：持续心情 | energy/affinity、衰减/恢复、节流持久化、App 参数面板 | 验证上下界、重启默认/恢复、错误数据回退；连续运行 30 分钟无表现风暴或内存持续增长 |
| H4：短音效 | 接入已明确可复用的非语言提示音，音量与静音控制；播放完成回调 | 用户清醒时听测；可立即静音/打断；播放与采集并行，录音标注播放区间和通道角色 |
| H5：有限对话 | 先文字输入，再 ASR；受约束 JSON 回应、超时、取消、离线退路 | 延迟和失败可见；旧回答被丢弃；离线仍可摸摸互动；无模型时前三阶段功能可用 |
| H6：动作表达 | 核对硬件修订、舵机坐标系、中位、方向和机械限位后，逐项加入小幅低速动作 | 用户清醒且在场实测；每个动作有停止、超时和限位；不允许模型直接给电机角度 |

每一步单独保存代码来源、参数、演示步骤和实测结果；上一阶段通过后再扩大范围。
H4 与 H6 需要未来另行安排清醒实测；今晚的无人值守许可不扩展为声音播放或舵机运动许可。

## 工程与资源边界

从原型提取纯状态逻辑时保留其 MIT 署名与许可证，并增加覆盖睡眠、取消、冷却和过期回调的测试。
原型表情是 SVG 源文件，需转换或用屏幕绘图实现，不能假定机器人直接解码 SVG。
音效优先选资料包 `audio/prototype/` 或 Kenney CC0，保留来源；原型 16 kHz 单声道资源需走明确播放适配。
角色图、原声和参考项目分别有来源条件；产品呈现采用自有角色设计，不把参考素材一并当作授权资产。
暂不加入视频情绪识别、自动追脸转头、全天云上传、多模型路由或复杂成长养成。
待真实记录和用户标注足够后，再决定语音/视觉线索是否改善体验，并报告误判而非只展示成功案例。
