# StackChan 数据采集实施计划

日期：2026-10-30。第一阶段只完成工程链路验证与 Android 数据采集，情绪宝宝后置。

2026-10-31 凌晨实施结果：**M0–M4 首版验收完成**，实机主机三流 60 秒通过，Android 模拟器实机记录 10 分 20 秒通过，导出、回放、链路中断/实际重启恢复和后台封存通过。模拟器经本机透明转发联调，真手机专项仍待做；以 [验证记录](collector-validation.md) 为准。操作见 [使用说明](collector-guide.md)，后续情绪宝宝的 H0–H6 计划见 [下一阶段计划](haro-next-plan.md)。

## 已确认的条件

- 用户授权编译、烧录自有固件、重启机器人和安装独立 Android App；原机备份保留。
- 首版机器人与 Android 位于同一局域网；今晚使用 Android 模拟器联调，真机专项验收另列。
- 允许采集现场图像、麦克风及传感器数据，测试数据仅留本机/模拟器。
- 机器人全程静音，舵机静止，不执行表情伴随动作、校准、回中或遥控测试。
- 工具链继续固定 ESP-IDF 5.5.4，基于官方 `f901cc2969189f3f0e96af1442c0f96e77e1e2c1`，开发分支 `feat/collector-v0.1`。

## 实现方案

固件增加专用采集启动入口，复用板级相机、音频、屏幕和 I²C 驱动，跳过官方账号、App、Avatar 服务、小智 Application 与自动 OTA。避免常规 HAL 初始化中的舵机和动作逻辑。采集任务独立于网络请求，内存有界；一份相机/音频输入向客户端提供，客户端慢时报告丢失，不无界积压。

Android 新建 `android/Collector/`，中文名称“StackChan 观察台”。连接、实时观察、录制、标记、会话查看、回放与 ZIP 导出形成完整操作链；默认不监听播放声音，不申请手机相机/麦克风权限。复用既有本机 Android SDK/JDK，不修改 Stick/PixelLock。

网络用本地 HTTP：8080 提供设备信息、传感器快照和 JPEG；8081 提供带时间戳的连续 PCM。设备生成独立配对令牌；不沿用出厂鉴权。首版 HTTP 不加密，限定可信局域网，不映射公网端口。协议见 [collector-protocol.md](collector-protocol.md)。

首轮提供相机、现有音频逻辑通道、IMU 六轴、头顶三区触摸、屏幕触摸和电池/充电状态。无现成驱动的其他传感器明确标注未支持，不返回模拟数值。视频目标为 320×240、约 2 FPS 起步；音频使用当前 24 kHz PCM16LE。以上是目标，须以实测报告为准。

## 里程碑与完成标准

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| M0 工程准备 | 独立分支、固定协议、设备身份、原机备份引用 | 不重复全量备份，不升级 SDK；串口确认属于 StackChan，不误刷 StickS3 |
| M1 固件与 App | 自有固件、独立 APK、协议解析测试 | 固件编译、APK 构建与签名检查、解析边界测试通过；无动作/扬声器输出路径 |
| M2 烧录与启动 | 镜像摘要、分区/写入校验、启动日志 | 确认实际运行版本、分区和固件摘要；关键外设真实初始化；保留 NVS 和校准 |
| M3 端到端采集 | 模拟器连接实机，图像/声音/传感器并发记录 | 图像可解码，音频帧完整且参数明确，传感器 valid/单位/时间可追踪；停止后文件可读取 |
| M4 使用与稳定性 | 标记、会话回放、ZIP 导出、断线恢复、持续运行报告 | 文件及索引匹配；重启/断线不静默拼接；统计帧率、音频 gap、内存和错误；至少一轮 10 分钟持续采集 |

真实手机的 Wi-Fi 环境、锁屏/后台保活、厂商省电策略及实际听感不能用模拟器结果替代。舵机不在本阶段验收范围。音频电平与PCM格式校验也不能替代用户对听感的确认。

## 记录与交付

- 每个记录会话包含 manifest、JPEG 帧与索引、PCM/WAV 与块索引、传感器 JSONL、标记/连接事件。
- 同时保留设备单调时间、boot_id、流序号和接收时间；时间戳是同步依据，不声称硬件级同步。
- 原始媒体、令牌、串口日志保存在已忽略的本地目录；报告只汇总必要指标。
- 完成后更新开发基线与交接记录，区分编译、主机测试、机器人实测、Android 模拟器和待真机验证。
