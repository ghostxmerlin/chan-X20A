# soul 进展与规划

整理日期：2026-11-07。

标注约定：
- **实测**：在真机或用户录音上测过；
- **推测**：还没有验证；
- **待定**：等用户拍板。

服务器地址、端口和令牌只放在本机 `.env`，不写进本文。

## 1. 目标（用户定）

- 做一只**宠物型陪伴机器人**，像一只猫，追求灵性，不做对话型功能机器人。
- **传感器只报告，不决策。** 遥控、急停和固定指令走本地快速规则；LLM 只提建议，由状态机决定能不能执行。
- **硬性要求：** 她出声时，语音输入要屏蔽或标记，防止她被自己的声音触发。
- **不重复造轮子。** 能用现成项目和官方例子就用，只写 soul 特有的部分。
- **录音全部保留。** 服务器、Mac 和将来机身上的录音，任何一侧都不自动删除。

## 4. 耳朵已经做到的（实测）

- **延迟：** Mac 到香港服务器，从说完到拿到结果，中位数约 0.9–0.95 秒。其中等静音 0.4 秒，计算 0.2–0.35 秒，其余是网络。
  - 跨境 TCP 连接会随机落到快（约 60 ms）或慢（约 210 ms）两条路径之一，建立后就固定。对策是建连后先测 RTT，落到慢路径就重连（推测有效，未实现）。
- **“是谁”不用等句子说完：** 开口约 1 秒就先报一次，再加上网络往返，约 1.3 秒能拿到。
- **误报修正：**
  - 蓝牙耳机会把静音切成数字零，害得人声检测误触发；加底噪后，误报的“陌生人” 15 → 0。
  - 轻微声音加 15 dB 门槛后，5 分钟内的声音事件 62 → 26；单下的敲击不报后 → 11。
  - “像不像人声”能把真话（0.53–0.85）和误判（≤0.06）分开。不像人声的片段不再标成“陌生人”。
- **Opus 上行：** 平均 5–13 kbps，原始音频是 256 kbps。压缩后各项门槛仍成立；声纹相似度中位数从 0.72 降到 0.62，所以要经 Opus 链路重新登记。
- **声纹跟着麦克风走：** 换麦克风后，同一个人只有 0.18–0.38，会被当成陌生人。正式登记要用机身麦克风，在她平时的位置录。
- **人声检测三选一：** 现用的 Silero、Silero v5、TEN VAD 都试过，没有明显更好的，维持现用。
- **录音存档：** 服务器和 Mac 每次连接都存音频和事件。服务器音频解码后的采样位置与事件里的 `pos` 逐点对齐。

## 5. 后续可做

**用户决定（2026-11-07）：**
1. ASR 模组先凑合用出厂的英文默认词表，不做中文固件；
2. **第一优先是机身耳朵和眼睛的连通性测试**，测试中肯定要调参，所以最迫切的是能在一个终端里同时看到两者的结果；
3. 眼睛和耳朵都纳入已经建好的“局域网内 StackChan 通讯监视”那一套体系；
4. 接线：ASR 接顶部黑色口，M12 接顶部蓝色口。

下面 5.1 的里程碑按这几条调整，具体做法待定。

### 5.1 第一个里程碑（推荐先做）：她用自己的耳朵听

目标：StackChan 自己把麦克风音频推到服务器，在网页上看到耳朵报的事件。

| 步骤 | 谁 | 内容 |
| --- | --- | --- |
| 1 | 用户 | 审 [soul-ear-interface.md](soul-ear-interface.md) v0.1，定下来后交给 codex |
| 2 | codex | 机身 WebSocket 推流：Opus 24 kHz、60 ms 一包，每包带 `SEA1` 头（序号 + 设备时间）；安静时也发；断线重连 |
| 3 | Opus | 服务器支持 `SEA1` 头和 24 kHz 双声道（第二声道是喇叭参考），按序号标出缺口，`meta` 里记设备身份 |
| 4 | Opus + 用户 | 用机身麦克风，在她平时的位置重新登记声纹：多录几句，一个人可以存多份 |
| 5 | Opus | 用真机录音离线重放，和 Mac 链路的数字对比，确认门槛仍然成立 |

### 5.2 服务端（Opus）

1. **耳朵正式化：**
   - 临时单元改成正式 systemd 单元，服务器重启后自动起来；
   - 代码目录从 `soul-spike` 改名；
   - 部署脚本 `server/ear/deploy.sh` 已入库。
2. **早报只报分数：** 开口 1 秒时的“是谁”只给相似度，不直接判“认识”。
3. **叫名字：** 两条路一起考虑：sherpa-onnx 关键词识别，或者 ASR 模组的唤醒词。同一句话两边都听到时短时间去重，以 ASR 为准（讨论里已定）。
4. **她自己的声音（硬性要求）：** 用喇叭参考声道，加上机身出声时发的 `self` 消息，标记或去掉她自己的声音。
5. **流式降噪 A/B：** 按 sherpa-onnx 调研报告第 11.4 节的调参清单做。
6. **大脑骨架：**
   - 事件队列加状态机，先用耳朵录音离线重放调试，同样的输入要得到同样的结果；
   - LLM 经 aihubmix 中转，之后试叙事式三步：写情景、续写、具体化。

### 5.3 机身（codex-astra）

1. 按接口规格推流（同 5.1 第 2 步）。
2. **读 ASR 模组：** 顶部黑色口是 Port B，GPIO8/9，串口 115200 8N1。把识别到的编号作为事件转给服务器；接口规格里要加一条 `asr` 消息（待定）。
   - 黄线和白线哪根是 TX、哪根是 RX，各文档写法不一，先两根都只接收试一下。
3. **读 M12 串口**，人脸和物体事件经 StackChan 转出去。
4. **眼睛资源接入首页。**
5. **喇叭播放：** 播放时立即发 `self` 标记，配合服务端的硬性要求。
6. **舵机回传：** 继续查根因。

### 5.4 需要用户做的

1. 审接口规格（5.1 第 1 步）。
2. **ASR 中文固件：**
   - 在智能公元平台从中文模板建产品；
   - 每条命令的串口输出改成 `AA 55 <编号> 55 AA`，`FF` 留给唤醒，`FE` 留给播报；
   - 关掉开机欢迎语，清空超时提示语。
   - 命令词表可以由 Opus 起草。
   - 烧录工具多半只有 Windows 版（推测）。
3. 定她的名字，也就是唤醒词。
4. 重新对一下架构（第 6 节第 1 条）。

## 6. 待决问题

1. **状态机跑在哪里。** 讨论记录里的“StackChan 守底线，UnitV2 管灵魂”，是在“大脑放公网服务器”决定之前提的，需要重新对一下：
   - 服务器、UnitV2、StackChan 各管什么；
   - 断网时她还能保留哪些反应。
2. **ASR 模组的回复语能否静音，或者换成猫叫。** 平台配置里有回复语和播报字段，能不能真正关掉没有验证。模块还有声纹和自学习开关，效果也没验证。
3. **断网时的录音能否补传（SD 卡）**，以及机身离线时听到的声音怎么算。
4. **叙事式 LLM 续写出来的内容**，算她的记忆，还是用完就丢。
5. **一个人存几份声纹，**按麦克风或场景各存一份。
