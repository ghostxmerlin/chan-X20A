# 内部 RAM / Flash 优化评估与紧凑观察台

后续实施：collector-0.4.32 已落实下表第1组日志去冗余。数组容量减少5,790 B，目标链接结果的BSS实际减少5,784 B（对齐差异）；其余迁移和Flash建议仍未实施。新增严格DMA free/largest遥测。触发原因与眼睛自然循环验证见[眼睛说明](soul-eyes.md)。

2026-11-08；固件基线 `collector-0.4.30`，源码基线 `eb2b227`，固定 ESP-IDF 5.5.4。
本轮只改 PC 网页，没有改固件、构建配置、分区、SD 内容或刷机。以下节省均为**候选容量**，不是已经获得的收益。
完整资源、接口和分区清单见 [资源与接口清单](resource-inventory.md)。

## 当前判断

内部 RAM 优化优先于 Flash。15:05:16（Asia/Singapore）设备重新在线，实时遥测为：

| 项目 | 字节 | 换算 |
|---|---:|---:|
| 内部可用堆 | 30,771 | 30.05 KiB |
| 最大内部连续空闲块 | 13,824 | 13.50 KiB |
| PSRAM 可用堆 | 5,975,844 | 5.70 MiB |
| 各内部堆区域历史最低空闲之和 | 1,319 | 1.29 KiB |

这是一个时间点，非负载测试的最差值；同一状态中 HTTP 音频客户端为2。最后一项不是同时发生的最低总空闲，也不能当 DMA 空闲。新增大块内部申请仍有风险；更充裕的 PSRAM 可承接普通缓存和合适的任务栈。

当前应用 `.bin` 为3,486,976 B（3.325 MiB），单应用槽5,177,344 B（4.938 MiB），余1,690,368 B（1.612 MiB）。Flash 还有增长空间，但旧显示和通用依赖值得收紧。

## 内部 RAM：先去冗余，再迁移

| 顺序 | 改动 | 可精算的对象/请求容量变化 | 验证要求 |
|---|---|---:|---|
| 1 | 日志 ring 从32行改成实际对外可见的9行 | 3,872 → 1,089 B，少 **2,783 B** | 保留截断、换行、脱敏和并发快照行为 |
| 1 | 屏幕日志拼接缓存按9×120字符＋8换行＋NUL推导 | 4,096 → 1,089 B，少 **3,007 B** | 用共同常量计算容量，防止以后扩展越界 |
| 2 | IMU 100条历史缓冲迁 PSRAM，保留现有历史长度 | 移出 **6,400 B**内部BSS | 处理分配失败，核验50 Hz写入、HTTP读取及恢复 |
| 2 | HTTP音频订阅改用PSRAM常驻worker栈 | 每路 **8 KiB**，最多两路 **16 KiB** | 保留请求生命周期、断开清理、两订阅并发；不能只换任务创建函数 |
| 3 | 遥控64包历史缓冲迁 PSRAM | 移出 **3,072 B**内部BSS | 保留锁和回调时序，不缩短历史 |

第一组日志去冗余共 **5,790 B / 5.65 KiB**。再加 IMU 和两路音频栈迁移，涉及约 **27.9 KiB**内部容量；迁移仍有指针/TCB/队列开销，实际空闲增量必须重建并实测。有一路订阅时，音频栈项只有8 KiB。

源码依据（前缀 `upstream/StackChan/firmware/`）：

- `main/collector/runtime_log.cpp:13,18,165`、`runtime_log.h:7`、`screen.cpp:42`：32行存储、9行快照和4 KiB拼接缓存。
- `main/collector/collector.cpp:131,328,833`：IMU历史；`:1125,1181`：两路8 KiB内部音频任务。
- `main/collector/remote.cpp:30,98`：遥控历史。

### 暂不优先压缩的部分

- LCD 20行缓冲改10行可少 **6,400 B**内部DMA，但会增加提交次数，必须测眼睛帧率、CPU和SD/LCD交接。
- I²S 6个描述符改4个可少约 **5,840 B**请求容量，但双向缓存约60 ms降到40 ms，音频抗调度抖动能力变小。
- main/LVGL/HTTP等内部栈缺完整高水位证据，不凭单次状态裁栈。播放、上传、眼睛、听觉共80 KiB栈已经在PSRAM，缩它们主要省PSRAM。
- Wi-Fi静态RX=3、动态RX上限=6，已经偏紧；动态TX上限32不是预占32包。`SPIRAM_TRY_ALLOCATE_WIFI_LWIP`还会改变允许的TX缓冲模式，不能承诺简单开启就净省几十KiB。
- 16 sockets是现有并发预算；Wi-Fi/lwIP IRAM优化已关闭，mbedTLS已用外部内存，不能重复计算收益。降低64 KiB内部保留池也不会增加物理RAM，并可能损害DMA保障。

### 更大的第二阶段，不直接相加

- 首页帧数据单独移SD可移出560,880 B（547.73 KiB）；保留Flash底图作无卡回退。必须选择预载或读取策略，不能重新引入LCD/SD总线竞争。进一步压缩也有空间，但实验压缩率不等于固件净收益。
- 通用网络库仍保留HTTP/MQTT工厂；HTTP stream和日志fmt共同拉入C++ locale。当前15个locale/facets/codecvt对象约148,608 B，须同时解除引用，不能保证全删。当前听觉的TCP/TLS及证书支持要保留。
- C++异常元数据 `.eh_frame` + `.gcc_except_table` 共230,765 B，**已包含在相关对象rodata内**，不能与旧app/locale收益重复相加。现有代码有throw/catch/dynamic_cast/stoi，不能直接关异常/RTTI。
- 全量证书bundle为68,987 B；换子集会改变可连接的TLS站点，需先明确服务端信任根。
- 编译已经启用体积优化和Newlib nano；裁ELF调试信息不会减少现有bin。BT/ESP-SR/ESP-DL/旧esp32-camera未见当前有效大块贡献，不能按源码目录大小声称可省空间。

建议依次做：**日志容量 → 音频订阅/IMU迁移 → 底图无损压缩/专用显示字体 → 旧依赖裁剪**。每一步单独比较bin/map和能力堆；显示、声音、相机、连续听觉、双订阅、SD写入并发要回归。DMA/Wi-Fi及异常配置放到已有测量之后。
