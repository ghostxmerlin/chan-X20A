# Mac 网页观察台

Mac 与机器人连接同一 Wi-Fi 后，双击仓库里的 `scripts/open-stackchan-monitor.command`，浏览器打开 **http://127.0.0.1:8787/**。本机服务已启动时直接打开网址即可。重启 Mac 后重新双击；不安装登录自启。

显示机身相机、麦克风电平与四秒包络、六轴曲线、电池/网络/环境/磁场、舵机实际反馈、ASR/M12 和连接事件。沿用 Android 使用的 collector 接口；新增控制按设备声明的能力开放。基础监控外，支持显式点击 M12、交互模式和舵机控制；打开/恢复页面不自动发送动作。

## 追踪与交互模式

具备 `interaction_modes=supported` 的新固件在 M12 面板提供三个独立开关。它们均为本次开机意图，开机默认关闭、不写入 NVS。按钮只在明确点击时提交；接收确认不直接改变按钮状态，实际请求与执行情况以新鲜遥测为准。旧固件的新模式按钮禁用，原手动检测、认人、待机及网页舵机控制保留。

- **追踪：** 需要 `face_tracking=supported`、M12 串口就绪且舵机已请求并启用。只调整水平轴，以本次有效实测位置为锚点 ±10°，单步 ≤1°；启动不回中，丢脸不搜索。页面分开显示锚点、目标与舵机实测，反馈/人脸过期、手动接管和保护故障有独立状态。故障保护提示关闭后重开；关闭追踪不要求当前反馈、舵机或 M12 就绪，仍须有效连接与当前 boot。
- **认人对话：** 需要 M12 串口就绪。任意已登记人脸视为主人，连续新鲜结果确认后启动已有的连续听觉与情绪回应；不是通用问答。页面显示主人、听觉归属与后端未就绪等状态。手动 stop 后不会自动重开；关闭认人只结束它自己仍持有的听觉意图，保留后来手动开启的听觉或录入。声纹仍只展示身份，听觉仍回应所有人。
- **高级预留：** 仅切换预留意图，始终显示“高级语音尚未实现”，不会由此启动新的语音后端、网络连接、声音或运动。

追踪与认人可同时开启：同时开启用 M12 认人模式，仅追踪用检测。后台模式保留眼睛首页。旧的“手动检测 / 手动认人 / 待机”仍为显式预览控制；手动切换会退出自动追踪与认人对话，防止争用视觉模式。M12 原始视频依然未接入。

新 ASR 映射为 **open 开启追踪、close 关闭追踪、next 随机台词**；next 保留 800ms 等待、忙碌丢弃和冷却，不排队。start / stop 连续听觉不变，turn on / off 保留手动视觉切换。台词面板展示 `asr_next` 来源和本次开机收到/接收/丢弃计数；旧固件仍显示 `asr_open` 与 open 映射。

实体遥控使用**摇杆页**：左切追踪、右切认人对话、上切连续听觉、下切高级预留，中心仍开关屏幕。四向不直接控制舵机；必须回中后再次拨动才触发，按住、首包、重连时偏转和对角输入不触发。现有协议不能区分摇杆与体感页。网页明确点击的左右 5° 和保存仰角仍保留，手动调角会退出追踪；不会自动重启保存俯仰姿态。

同源 `POST /api/control` 仅接受 `{action:"interaction",mode:"tracking"|"recognition"|"advanced",enabled:boolean,boot:string}`，经服务端白名单转成带鉴权和 `X-Boot-Id` 的 `POST /v1/interaction {mode,enabled}`。状态过期、旧 boot、未知字段或缺少能力时拒绝，排队发送前再次核对。失败不自动重发，页面刷新/恢复/后台轮询均不启用模式。1366×768 保持原紧凑一页布局，长状态可悬停查看。

本节描述新代码行为；部署、真人识别、追踪方向、实际声音与机械效果需分别按最新验证记录确认。以下带版本的小节保留历史信息，ASR 与实体遥控映射以本节和实时固件能力为准。

## 启停

collector-0.4.28 候选增加“语音后端 · 配置与声纹”。点击“使用本机现有后端”从根目录私密 `.env` 读取 `SOUL_EAR_URL` / `SOUL_EAR_TOKEN`，经鉴权写入本体 NVS；密钥不返回浏览器、不进入 curl 参数。也可以手动填写 ws/wss IPv4 地址和密钥，空密钥保留旧值。保存后待机，开机也默认待机。

说 **start** 开始本体直连 sherpa-onnx 连续监听，说 **stop** 停止；网页也有明确按钮。此监听与“在 Mac 听麦克风”的按钮独立，关闭网页不会停止。回应所有人，声纹仅显示身份。完整语音的 happy/sad/angry/fearful/disgusted/surprised 标签映射到本体台词与眼睛，neutral/unknown 不播放，至少间隔10秒；自身播放被标记排除。后端沿用原录音留存行为。

填写姓名后点击“录入五句话”，通过本体麦克风说五段1–12秒的自然语音，句间停顿；120秒未完成自动取消。录入期间暂停情绪回应，完成后恢复原监听状态；取消/断线不保存半成品。同名默认拒绝，需勾选重新录入，服务端先备份现有声纹库。页面支持展示身份、转写、情绪标签、进度和错误。新固件尚未刷入时按钮保持禁用；主机测试不等于真人或实机验收。

collector-0.4.34 起的“眼睛表情”支持三款眼睛的自然循环：选款后点“自然循环”应用，随机表情与停顿在本体运行。选择表情可“播放一次”，结束自动回循环；“回到待机”结束当前表达，“恢复原首页”才关闭眼睛。旧固件仍显示“启用款式”。页面刷新/重连不发控制。ASR next（旧固件 open）的本体台词起声后配近似表情，网页台词点播不自动配表情；手动表情优先。资源安装通过Wi-Fi，无须拔卡，见[眼睛使用与协议](../../docs/soul-eyes.md)。

需要 macOS 系统 curl 和 Node.js 24；无 npm 依赖。

```sh
node web/monitor/service.mjs start
node web/monitor/service.mjs status
node web/monitor/service.mjs stop
node --test web/monitor/*.test.mjs
```

服务仅监听 `127.0.0.1`。有网页打开才采集；最后一个页面关闭/暂停后 1.5 秒释放设备连接。多个页面共用一个设备音频流和一份图像/遥测轮询。Android 原有 App 可继续使用；两个主端口请求按顺序执行，音频最多额外占一个设备客户端。日志为本机 `logs/stackchan-monitor.log`。

“开启监听”只在 Mac 播放麦克风第一通道；默认关闭，切后台、暂停、断线、机器人重启时关闭，恢复连接不会自动播放。电平显示与声音外放互相独立。不保存录像或录音。

## 首次绑定或地址变化

开发机已有本机绑定时无需再输入。换电脑/设备或 DHCP 改地址时，在 `.private/stackchan-monitor.json` 配置已有配对信息，再重启服务。该文件已被 Git 忽略，权限必须为 `0600`。下面都是占位值：

```json
{
  "address": "http://192.168.1.100:8080",
  "device_id": "从机器人配对页读取",
  "token": "从机器人配对页读取的32位十六进制令牌",
  "port": 8787
}
```

```sh
chmod 600 .private/stackchan-monitor.json
node web/monitor/service.mjs stop
node web/monitor/service.mjs start
```

地址只接受 IPv4 HTTP 原点，不接受路径或重定向。每次连接先做随机挑战/HMAC 身份验证，通过后才发送 Bearer。令牌通过 curl 标准输入传递，不进入浏览器、命令参数或日志。本机 API 拒绝外部 Host/Origin；仅 `/api/control` 接受当前页面同源的 JSON POST，其他接口仍只读。不要把配对令牌放到网址、源码或截图里。

当前固定使用配置地址，不包含 Android 的 UDP 自动发现。若网页长时间等待，先确认机器人联网、同一 Wi-Fi、配对页地址与配置一致。服务端用系统 curl：现场 Node/Python 直连曾报 EHOSTUNREACH，而系统 curl 同地址成功；这里绕过该现象，并未认定或修复其根因。

## M12 独立区域与温度（0.4.18）

M12 与 ASR 分开显示。独立 M12 面板画出串口回传的 640×480 人脸框及置信度；这是检测坐标示意，并非 M12 原始相机画面。人数为零的结果仍参与计数。检测更新率用设备累计结果数和单调时间的五秒窗口计算，至少一秒数据才显示，不能当作视频 FPS。待机、切换、断线/重启清空旧框；检测结果 1.5 秒未更新标成过期并显示 0 FPS。

StackChan `collector-0.4.18` 新增 ESP32-S3 内部芯片温度与最近两分钟趋势，约一秒采样；标注为芯片温度，不代表外壳/室温。传感器配置范围 20–100°C，读取失败或超过三秒没有有效值时显示不可用。资料见 [ESP-IDF 5.5.4 温度传感器说明](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/api-reference/peripherals/temp_sensor.html)。

**M12 实时温度已接入。** Mac 独立通过 SSH 每两秒读取 M12 的 `TEMP_R`、Wi-Fi 接口和当前工作进程，网页显示实时芯片温度、网络监控连接和进程。M12 与 StackChan 的连接分开判断，本体掉线时仍可显示 M12 温度；超过六秒、读取失败、暂停或断线时清空温度。多个网页共用一个 SSH 连接，最后一页关闭后释放。只读系统状态，不开启人脸检测，不拉视频，不写设备配置。

本机 `.private/stackchan-monitor.json` 的可选 `m12` 对象包含 `host`、`user` 和 `host_key_alias`。`host_key_alias` 必须对应本机 `~/.ssh/known_hosts` 中**此前已核实的 M12 身份**；设备换 IP 时更新 `host` 并重启服务，保留身份校验，拒绝未知或改变的主机密钥。出厂账号使用旧 M12 工具的公开出厂密码；设备已改密码时仅在私密配置中设置 `m12.password`。密码通过 ASKPASS 环境传递，不放到网页或命令参数中。

当前检测框仍为串口结果坐标示意，**原始视频尚未接入**，不会为了显示视频自动切换 M12 工作模式。

## 读数与边界

- 相机来自 CoreS3。M12 通过串口提供状态/检测结果，没有把 M12 的镜头流传到这个接口；不在机身画面上叠加 M12 坐标。
- 遥测/相机 1.5 秒、音频 1 秒无新数据就显示过期；重复序号不延长有效期。断线/重启清空缓存图像和曲线。
- 麦克风 RMS 使用第一通道，固定 −60…0 dBFS 电平尺，无自动增益；线条为真实样本最小/最大值。音频线缆映射的固件标志仍是未校准，不据界面推断声学质量。
- 六轴共用最近四秒；加速度 m/s²、角速度 °/s 分别显示量程。磁场为传感器坐标 µT，不是已校准航向；接近 raw 不是厘米。
- 舵机只显示有效实测角度，并单独列出保存值和启动姿态。这里不修复已有舵机通信/归位问题。
- M12 “请求”不等于已执行；“设备报告”和最近串口接收时间一起看。待机没有持续回包是可能的，旧报告不是当前活性的证明。
- 事件记录仅是连接和遥测状态变化，最多保留 120 条，服务重启清空。完整固件 log 仍需 USB/机身日志页。

实机、浏览器和审阅记录见 `docs/session-handoff.md` 最新条目；主机测试不等于真人 ASR、机械动作或长时间音频验收。

## 网页基础控制（collector-0.4.20 起）

- M12：开始人脸检测、退出待机。经 StackChan 统一切换 M12 与机身页面，ASR turn on/off 和触摸退出仍有效；不启用自动识别或自动唤醒。请求接收与设备工作报告分别显示。
- 舵机：启用/停用；按机器人自身方向每次左/右 5°，单次点击、速度100。步进使用一秒内有效左右反馈，需轨迹结束，受 ±128° 和设备实际机械限位共同约束。无效反馈/运动中不接受新步进；一秒过期或实体遥控接管会取消排队步进。停用取消待执行动作，重新启用不重放。
- 仰角：输入5–85°、0.1°步长，点击“保存并应用”；沿用原固件持久化，同时立即尝试调整，作为下次开机设置。输入草稿不会被后台轮询覆盖。反馈不可用/运动中暂不能应用，保存/轨迹结束不代表实测到达。
- 设备旧固件、监控暂停、断线或状态过期时禁用操作。每次请求核对当前boot，失败结果不确定时提示用户查看实时状态，不自动重发。暂停监控只暂停此页采集，停止动作请用“停用舵机”或“M12退出待机”。

实现未新增依赖。配对令牌留在本机，浏览器只提交白名单操作。`/v1/remote`、`/v1/settings/pitch` 对旧Android保持兼容；新网页附带 `X-Boot-Id`。新增鉴权 `POST /v1/m12/view {enabled:boolean}` 和 `POST /v1/motion/yaw-step {delta_deg:-5|5}` 强制当前 `X-Boot-Id`，202只表示接收；实际模式/步进状态从遥测读取。

本轮实机：M12 网页开启检测后显示1张人脸、约4.1结果/秒、79°C，随后ASR turn off回到Audio FFT；用户测试舵机后反馈“有点动作”。用户设置30°已保存，但俯仰实测-3.7°不符合启动条件，仍feedback_unavailable；未认定机械到位或修复历史UART/反馈问题。最新保存值以实际遥测为准，不自动恢复旧10°。

### 历史：手动认人与遥控俯仰（collector-0.4.23）

M12 增加“人脸识别（认人）”，使用设备已有登记资料，显示每张脸的名字或未匹配、匹配度及识别结果/秒。切换、断线和结果过期清空身份；检测与识别分别计数，不是视频帧率。仍不传输 M12 原始视频，也不自动登记人脸。认人是手动模式，ASR turn on 选检测，turn off/离开机身人脸页回待机。再次明确点击同一模式会重发切换命令；页面刷新、恢复监控不发动作。

新鉴权接口 `POST /v1/m12/mode {mode:"standby"|"face_detector"|"face_recognition"}` 强制 `X-Boot-Id`，旧 `/v1/m12/view` 保持兼容。页面认人按钮只在 `m12_recognition=supported` 时开放。

实体遥控上下恢复俯仰舵机，保留 5–85° 限位、原厂平滑与扭矩释放；左右方向和中心开关屏不变，上下不再触发表情。中心协议首包只建立俯仰基线，不变心跳不会覆盖启动/网页设置；后续上下改变接管俯仰，新的保存设置再接管。停止取消动作，重新启用不重放旧输入。保存角和校准不因遥控变化而写入。`motor.pitch_target_deg` 只在实体俯仰持有控制时有值，`pitch_owner` 标记来源；实际角度仍来自反馈。

M12 识别启动报告与识别结果分别记录：`last_recognition_report_us` 只说明程序报告，不能证明已认出人或持续运行。官方认人程序在无人脸时可以不输出结果，所以启动报告会停止未应答重试；新鲜人脸结果仍是展示身份的必要条件。

俯仰回中修正（0.4.23）：现场摇杆松手发 47.1°（来自发送端 ADC 标定），不再直接用作机械目标。16 字节 center_v1 输入以该值 ±0.5° 为中位，映射到最新保存仰角，两侧映射到 5°/85°；8 字节旧协议仍为绝对角。修改保存角不会让下一次不变心跳接管。当前16字节协议没有摇杆/IMU模式标记，因此IMU模式也采用这条中位映射，不能声称IMU绝对角语义未变；现场验收范围是摇杆。

## 历史：本体随机台词（0.4.26）

“随机台词”面板提供40条选择、播放所选和随机播放。声音从StackChan本体发出；网页的“开启监听”是另一项麦克风监听功能。collector-0.4.35 起 ASR收到`next`（0x1B无value；旧版为open）时在本体随机选一条，等待800毫秒后启动播放，给ASR模组的OK留出时间；网页点播不增加此等待。网页关闭、Mac服务停止仍可触发。`turn on/off`继续控制M12。

仅显式请求播放，打开/刷新/重连不重放。忙时拒绝并丢弃新的ASR触发，无队列；随机避免与上一次台词连续相同。播放结束后ASR冷却1.2秒，实际回声环境仍需现场验证。显示设备播放状态、当前台词、来源和已提交音频量；完成状态不证明人耳听感正常。

此版实体遥控上下已屏蔽，左右和中心开关屏保留；网页保存仰角/启动角仍保留，不再用遥控试验重负载上下运动。

音频来自本机`voice/outputs/stackchan_playable_40.json`及其引用的两批资源目录。源PCM哈希校验后转换16kHz单声道IMA ADPCM，嵌入应用分区；解码后原地插值回24kHz，保持原始帧数和完整时长，不改共享I²S配置。处理有损，40条C++解码/插值与FFmpeg加独立Python参考逐字节一致；听感需单独确认。生成资源在`.private/voice-library`，不提交音频或现场文件。构建前执行：

