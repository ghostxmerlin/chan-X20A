基于 M5Stack StackChan（CoreS3 + 原装底座）的本地采集与遥控项目。将摄像头、麦克风、六轴、磁场、光照/接近和官方遥控数据实时传到 Android，支持观察、录制、标记、回放和导出；不依赖出厂账号或云服务。

本仓库 fork 自 [m5stack/StackChan](https://github.com/m5stack/StackChan)，开发起点为 [`f901cc2`](https://github.com/m5stack/StackChan/commit/f901cc2969189f3f0e96af1442c0f96e77e1e2c1)。保留上游提交历史，官方源码统一放在 `upstream/StackChan/`。

已绑定的观察台将设备身份、凭据和地址保存在应用私有空间，打开或返回前台时自动连接，日常无需再输配对码。地址变化时通过 UDP 发现和 HTTP 挑战确认同一设备，再发送鉴权请求；不广播凭据，也不提供全新手机匿名绑定。本开发安装已迁移已有凭据，并确认不带地址/令牌启动参数即可连接。模拟器仍使用本机转发，不能据此宣称真手机或模拟器的 IP 变化恢复已实测通过。

抬头角度由用户明确设置为 **5–85°、步进 0.1°**，机器人保存配置并尝试执行；以后重启采用该设置，未保存时默认 13°。界面分开显示保存状态、动作状态和实际反馈，保存成功或轨迹完成都不等于实测到位。自动连接不会重复发送角度命令，停止控制取消当前动作；摇杆仍只控制左右，上下只触发表情，中心仍控制显示。

## 目录

| 路径 | 内容 |
| --- | --- |
| `upstream/StackChan/firmware/` | 基于官方源码的 ESP32-S3 采集固件 |
| `upstream/StackChan/remote/` | 官方遥控器源码及已部署的中心按压输入扩展 |

| `server/ear/` | soul 的耳朵服务端（sherpa-onnx：人声检测、识别、声纹、声音分类）和 Mac 测试客户端；真实服务器配置放根目录 `.env`，不提交 |

`upstream/StackChan/` 是仓库中的普通源码目录，无需初始化 submodule。构建依赖由其 `firmware/repos.json` 和 `dependencies.lock` 固定。

## 构建与使用

固定使用 **ESP-IDF 5.5.4**；Android 使用 **SDK 35 / Build Tools 35.0.0 / JDK 17**。新检出的工具链准备步骤见 [构建说明](docs/build.md)。环境就绪后，在仓库根目录运行：

```sh
./scripts/idf.sh build
bash android/Collector/test-host
bash android/Collector/build-app
python3 -B -m unittest discover -s tests -v
```

设备连接、记录和数据导出见 [使用说明](docs/collector-guide.md)，通信格式见 [协议](docs/collector-protocol.md)。部署前需核对设备与活动分区；项目内的开发设备偏移不能直接用于其他机器。

本轮遥控器已核对为 ESP32-PICO-D4 / 4 MB，完成整片备份与独立校验，仅写其实际 `factory / 0x10000` 应用区。首次启动前读回确认应用写入范围以外字节未变；运行时可能产生 PHY 校准等 NVS 写入，不能据此声称 NVS 永不变化。机器人仍使用独立核对的 `ota_1 / 0x510000`，两者偏移不可混用。

三款正面眼睛的预览、状态清单、SD 文件布局和 ESP-IDF／LVGL 接入约束见 [眼睛资源使用说明](docs/soul-eyes.md)。

soul（宠物型陪伴机器人）的整体进展、分工和后续计划见 [soul 进展与规划](docs/soul-roadmap.md)。耳朵服务端的用法、配置和部署见 [server/ear](server/ear/README.md)；服务器地址、端口和令牌只放在本机 `.env`（格式见 `.env.example`）。

M12 摄像头通过 Grove 接 StackChan（由 StackChan 供电，串口 115200）。它的连接方式、设备接口、散热限制、官方源码分析和后续规划见 [M12 探索记录](docs/m12-unitv2.md)；Mac 监控面板的用法见 [m12/panel](m12/panel/README.md)。

仓库只发布源码、配置与整理后的验证结果。凭据、签名私钥、原机备份、原始串口日志、现场图像/录音和本机构建产物保留在本地，不随 Git 上传。历史文档中的 `logs/`、`artifacts/` 链接是本地证据路径，不是公开下载链接。
